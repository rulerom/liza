# Scoped channel B0 — C runtime probe

This is an isolated experimental C prototype for the [scoped channel contract](../../docs/scoped-channels-contract.md), not a Liza API or a production runtime. One producer and one consumer exchange `u32` through a bounded FIFO guarded by one mutex (POSIX) or SRW lock (Windows). The full allocated `channel` object includes metadata, alignment and all preallocated slots. `ch_create` checks the byte budget and integer limits before allocation. OS/allocator overhead and thread stacks are outside that budget. No send, receive or close allocates memory. Caller must join every accessing thread before destroying the channel; C cannot enforce SPSC role or scoped ownership.

```sh
python3 -m unittest discover -s experiments/scoped_channel -v
```

The native test checks capacity, budget, FIFO, wraparound, Full/Empty/Closed, drain after sender close, discards and repeated close, 1000 send/receiver-close races, and 100,000 sequential messages per run for capacities 1/4/16/64. Separate fault injection simulates allocation failure; a negative control deliberately corrupts the queue on Full and must fail. Testing uses bounded subprocess timeouts. OS threads and mutexes are real; this is still testing, not a universal correctness proof.

`try` does not wait for queue space or a message, but can wait to acquire the mutex. Optional `CH_MEASURE` instrumentation records lock acquisitions, failed try-locks (contention), aggregate and maximum wall-clock wait and hold times. `python3 experiments/scoped_channel/measure.py --output /tmp/channel-measure.json` collects three instrumented samples per capacity. The clock and try-lock instrumentation changes the timing, memory layout and contention; hold time includes OS preemption. The report has aggregate values and maxima, not p99, and does not establish uninstrumented latency or throughput. Counters are intended for short runs and do not saturate. Worker group creation failure, compiler endpoint checks, explicit join enforcement, integration with Liza, fault injection for mutex initialization and independent formal models remain work for subsequent stages. No socket, region or arbitrary value is transferred.

The saved `results/apple-m4-instrumented.json` contains three diagnostic runs on one Apple M4/macOS host. For 100,000 messages per sample, observed try-lock contention ranged from 13.5–13.9% of acquisitions at capacity 1 to 2.8–2.9% at capacity 64. Busy retries count as additional acquisitions, so percentages are not fractions of messages delayed. Both threads use busy-yield loops; this is not a network workload. Timer resolution, sampling overhead and scheduler preemption limit interpretation of wait/hold times; maxima are not latency percentiles. The report records the dirty source state and hashes of the exact measured files, rather than implying that the preceding commit contains the instrumented sources.
