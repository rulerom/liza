# Performance Parity P2 — состояние и aliasing на LLVM 23

Первый диагностический срез S2-A/B/C. **Production backend, Core, runtime и алгоритм
JSON не изменены.** Цель ≥90% Rust остаётся инженерным ориентиром, пока не достигнутым.
Эксплуатационная приёмка Gateway и R0/VN0 сохраняют приоритет; эта работа не расширяет
существующие гарантии Verified.

## Переход на LLVM 23

Основной стенд Liza и общий C driver пересобраны Homebrew Clang **23.1.4**.
Rust 1.99.1 использует LLVM **23.1.3**: сравнение одной major-версии, но не тождественных
pipeline или patch-версий. Apple Clang 21 оставлен отдельным контролем в той же
рандомизированной серии. Полные версии, flags, target и source snapshots сохранены.

На Apple M4 полный набор компилятора с LLVM 23 прошёл: **405 тестов, 11 платформенных
пропусков**, включая O0/O2 и сетевые сценарии. Это локальная macOS-приёмка, а не
результат Linux/Windows. [Выбор Clang](getting-started.md#llvmclang)
уже поддерживается через `--clang` или PATH; новая возможность языка не требуется.
Закреплённые toolchains отдельных Verified-экспериментов не заменяются автоматически.

## Проверяемые гипотезы

| Срез | Эксперимент | Граница вывода |
| --- | --- | --- |
| S2-A | Разложить nonvolatile aggregate loads/stores простых integer-структур по полям | Проверяет одну форму представления; не весь потенциал SROA |
| S2-B | `noalias` только для state на C-границе benchmark `stream_feed` | Обоснован отдельными живыми allocations driver, не всеми правилами M0 |
| S2-C | Предварительный стандартный Clang O1 → IR, затем O0/O2 | Проверяет порядок стандартных passes, не доказывает избыточность guards |

Есть отдельный Cost400 control и сочетания scalar/alias + Cost400, чтобы не
приписывать эффект inlining новому представлению. Все варианты используют прежние
исходники алгоритма и checked-операции. Scalar-преобразование затрагивает 5 мест
загрузки/сохранения integer-only структур, без volatile/atomic/resource полей.
В staged-варианте O0 означает backend O0 **после O1 preprocessing**, а не полностью
неоптимизированный путь из исходника.

## Результаты скорости

Apple M4, O2, generic CPU, одинаковый C ABI без LTO, шесть документов ~256 КиБ,
чанки 2048, прогрев и ~16 МиБ на sample. 10 перемешанных серий, **540 samples**.
Таблица — медианы МиБ/с. Для смены toolchain сравниваются столбцы 21 и 23 внутри
этой серии, а не исторические числа P0/P1.

Ни одна новая гипотеза не дала устойчивого улучшения на всём корпусе. Полные
комбинации с Cost400 находятся в отчёте; они также не закрывают разрыв до Rust.
Смена LLVM сама по себе не объясняет отставание. Различия в несколько процентов
не объявляются надёжным выигрышем по одной серии.

Особенно показателен Alias: байты секции `.text` **идентичны** Default. То же верно
для Alias+Cost400 относительно Cost400. Извлечение Mach-O секций и SHA-256 сохранены,
размеры сверены с системной утилитой `size`. Следовательно, вариацию времени этих
пар нельзя считать свидетельством полезной оптимизации от alias-аннотации.

## Что показывают счётчики S2-A

Инструментируется уже оптимизированный IR. Во время feed и его callees считаются
операции над диапазоном физического `JsonState`; временные stack allocations,
входной буфер и bulk intrinsics в эти state-счётчики не входят. Размер состояния
получен из benchmark ABI: 184 байта у Liza, 176 у Rust. Результаты ниже — на входной
байт ASCII, включая одинаково нормализованные прогрев и один проход.

| Метрика IR | Liza default | Liza scalar | Rust |
| --- | ---: | ---: | ---: |
| Load operations внутри state | 6.401 | 13.401 | 8.376 |
| Store operations внутри state | 2.925 | 9.925 | 4.925 |
| Сумма allocation spans загрузок, байт | 71.952 | 65.952 | 43.552 |
| Сумма allocation spans сохранений, байт | 58.350 | 52.350 | 34.350 |
| Условные IR transfers | 17.376 | 17.376 | 14.351 |
| Overflow intrinsic calls | 2.350 | 2.350 | 0 |

**Это не hardware memory traffic или число ARM64-инструкций.** Aggregate/vector
load считается одной IR-операцией; allocation span включает padding. После
разбиения UTF-8 структуры число операций увеличивается на 7 загрузок и 7 сохранений,
а span уменьшается на 6+6 байт за счёт padding. Такое изменение само по себе не
доказывает уменьшение реального трафика CPU. Исходный LLVM IR и assembly сохранены
для проверки того, во что эти операции реально снижаются.

Rust сохраняет overflow checks через сравнения/ветвления; ноль intrinsic calls
не означает отключённую checked-арифметику. Аналогично 17,4 против 14,4 transfers
не доказывает, что конкретные три ветвления лишние. Staged-вариант дал 18,376
transfers/байт, не уменьшив этот показатель.

В Liza по-прежнему виден полный value-based roundtrip `Utf8StreamState`: outer
JSON имеет mutable API, но UTF-8 helper получает и возвращает агрегат. Scalarization
поля не устраняет эту границу и не создаёт автоматически регистровое состояние,
живущее между итерациями. Это конкретный кандидат следующего узкого эксперимента,
а не утверждение, что весь остаток отставания вызван только им.

## Граница S2-B и отрицательные контроли

По [LLVM LangRef](https://releases.llvm.org/21.1.0/docs/LangRef.html#noalias),
параметр `noalias` накладывает ограничения на обращения к изменяемым locations во
время вызова. Нарушение контракта — undefined behavior. Из названия `borrow mut`
не следует автоматически, что нужное LLVM-обязательство установлено для каждого
lowering, производного view и внешнего вызова.

Здесь driver держит входной буфер и state в независимых живых allocations и
передаёт их в одну известную границу. Только это основание используется для
атрибута; ни внутренние функции, ни все mutable-параметры им не помечаются.
Результат не опровергает потенциальную пользу более точной локальной alias metadata.

Нативный отрицательный контроль записывает через два указателя и читает первый.
При совпадении адресов корректный результат — 2. Заведомо неверный `noalias`
позволяет O2 вернуть 1. Проверенный overlap path использует unannotated fallback
и сохраняет 2; независимые аргументы дают 1. Неверный вызов намеренно нарушает
LLVM-контракт и используется только как контроль обнаружения, не как допустимая
семантика программы. На этой иллюстрации нельзя основывать общий borrow checker.

## Размер кода и приёмка

| Вариант LLVM 23 | `.text` объекта, байт |
| --- | ---: |
| Default / Alias | 7188 |
| Scalar | 6628 |
| Staged | 7284 |
| Cost400 / Alias+Cost400 | 8244 |
| Scalar+Cost400 | 7876 |

Для сравнения Clang 21 Default — 7320 байт. Уменьшение общего `.text` Scalar
не сопровождалось устойчивым ускорением; размер не является заменой измерения.
Stack records, offsets state-accesses и все шесть нагрузок доступны в артефактах.

Приёмка включает:

- полный набор компилятора LLVM 23: 405 тестов, 11 skips;
- по 21 существующему тесту для Scalar и Staged, включая snapshots, traps до RHS
  I/O, записи перед Err и RTP;
- 6 тестов counters/transforms/alias controls на LLVM 23;
- 6785 partitioned cases на каждый executable семи вариантов O0/O2, Rust и
  Clang 21 control; 2091 CLI check;
- совпадение **всего partitioned probe** и шести workloads для инструментированных
  binaries, которые никогда не участвуют в измерениях скорости.

Rust IR содержит новые lifetime-intrinsic signatures, поэтому его untimed counters
компилируются совместимым LLVM 23. Таймируемый Rust — исходный rustc binary.
Счётчики снимают несовместимые с инструментированием memory/capture/alias annotations;
отдельный regression test защищает имена intrinsic от ошибочного удаления `noalias`.

## Решение

LLVM 23 пригоден для дальнейшего локального исследования и прошёл указанную
macOS-приёмку. Новые оптимизации в production не включаются: существенный выигрыш
не установлен. Цель 90% Rust ещё не достигнута; S2-C пока не содержит доказанного
устранения guards на основании инвариантов. Следующие изменения должны иметь
отдельный контракт и проверяемый эффект, без ослабления traps или приоритета Gateway.
