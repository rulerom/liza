## Один язык. Три нативные платформы.

Liza компилирует программу в машинный код через собственный Semantic IR и
LLVM/Clang. Результат — обычный исполняемый файл выбранной host-платформы.
Код программы не транслируется в C; небольшая платформенная runtime консоли
написана на C и связывается с программой.

| Платформа | Проверенная архитектура | Нативный результат |
| --- | --- | --- |
| **Linux** | x86-64 | ELF executable |
| **macOS** | ARM64 / Apple Silicon | Mach-O executable |
| **Windows** | x86-64 | PE `.exe` |

Сейчас программа собирается на той системе, где будет запускаться.
Кросс-компиляция ещё не реализована. Для сборки нужны Python и Clang;
для запуска готового бинарника они не требуются. Зависимости от системных
библиотек сохраняются — это пока host-сборка, а не freestanding runtime.
[Требования и команды для каждой платформы](getting-started.md).

## Hello, Liza!

Этот код уже работает. Вывод — явный эффект `io`, а отказ вывода возвращается
как значение `Result`.

```liza
fn main() -> u32 : io {
    match console.println("Hello, Liza!") {
        Ok(written) => { return 0 }
        Err(error) => { return 1 }
    }
}
```

Linux / macOS:

```sh
python3 -m liza build examples/hello.liza
./build/hello
```

Windows, в **x64 Native Tools Command Prompt**:

```bat
python -m liza build examples/hello.liza
build\hello.exe
```

`build` сохраняет бинарник в `build/`. Команда `run` собирает временный файл,
запускает его и затем удаляет. [Быстрый старт](getting-started.md) ·
[Текст, консоль и ошибки I/O](io-model.md).

## Что определяет Liza

<div class="liza-concepts">
  <section>
    <h3>Значения прежде адресов</h3>
    <p>Структуры и массивы — логические значения. <code>copy</code> создаёт независимое значение, <code>move</code> прекращает доступ через исходную привязку. Универсальных указателей в языке нет.</p>
  </section>
  <section>
    <h3>Определённая семантика</h3>
    <p>Фиксированная ширина целых, явные режимы арифметики и обязательные проверки границ. Оптимизация сохраняет результат, порядок внешних действий и обязательные traps.</p>
  </section>
  <section>
    <h3>Доступ без передачи владения</h3>
    <p>Readonly <code>View&lt;T&gt;</code> даёт ограниченный доступ к части массива. Лексическое заимствование не позволяет переместить или заменить владельца, пока представление действует.</p>
  </section>
  <section>
    <h3>Явные эффекты и ошибки</h3>
    <p><code>pure</code> не может вызвать <code>io</code>. Ожидаемые ошибки представлены <code>Result</code>; <code>match</code> требует разобрать все варианты. Trap остаётся нарушением вычислительного контракта.</p>
  </section>
</div>

**Контролируемая стоимость — проектная цель, а не универсальная гарантия.**
Она означает возможность управлять аллокациями, копированием и другими
затратами, а не одинаковую производительность на всех процессорах.
Отсутствие копий и heap-аллокаций проверяется в конкретных трактах;
для всех конструкций языка такое обещание пока не дано.

## Уже можно выразить

| Задача | Что есть в языке |
| --- | --- |
| Вычисления над бинарными данными | Целые 8–64 бит, битовые операции, сдвиги, checked/wrapping/saturating-арифметика |
| Алгоритмы с локальным состоянием | `var`, SSA, `if`, `while`, `break`, `continue`, функции и ранний `return` |
| Составные данные | Структуры, фиксированные массивы, индексация с проверкой границ, `copy`/`move` и readonly views |
| Ожидаемые ошибки | `enum`, исчерпывающий `match`, `Option<T>`, `Result<T,E>` |
| Нативный консольный инструмент | `Text`, вывод текста, байтов и целых, проверяемые `pure/io` |

Один из работающих примеров — **парсер RTP-заголовка**: он принимает
`View<u8>`, проверяет длину, версию, CSRC, расширение и padding, затем возвращает
`Result<RtpHeader, ParseError>`. Передача view парсеру не копирует входной пакет
в проверенном тракте. [Эталонные программы](reference-programs.md).

## Куда движется язык

Цель Liza — небольшой выразительный язык, на котором можно вырасти от разбора
бинарного пакета до сложного серверного приложения: мессенджера,
видеоконференцсвязи или отказоустойчивого кластера.

Следующие задачи — коллекции заданной вместимости, расширение файлового I/O,
строки и коллекции. Системные эффекты,
конкурентность, сеть и self-hosting — дальнейшие этапы.

Liza остаётся экспериментальным языком: синтаксис и контракты могут меняться.
Записи файлов, динамических коллекций, пользовательских модулей, общего FFI
и задач пока нет. Первая модель владения реализована для файлов; пользовательские ресурсы ещё проектируются.

*Liza — a systems programming language for portable computation with well-defined semantics and explicit control over execution costs.*
