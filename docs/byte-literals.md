# Байтовые литералы

`b"..."` создаёт readonly `View<u8>` на константные байты в бинарнике.
Это статическое storage и небольшой дескриптор адреса/длины: heap allocation,
Region и преобразования в `String` или `Text` нет. Длина известна компилятору;
завершающий NUL не добавляется.

```liza
fn first(data:View<u8>)->u8 {
    return data[0]
}

fn main()->u32 {
    method=b"PLAY"
    if method.len!=4||first(method)!=80 {return 1}
    if first(b"Content-Length")!=67 {return 2}
    return 0
}
```

Литерал имеет тип `View<u8>` независимо от контекста. Можно передать его
прямо в функцию, ожидающую такой view, присвоить локальной привязке,
читать байты по индексу, использовать `.len` и создавать локальные subviews.
`b""` — допустимый пустой view. Границы индекса/subview проверяются как обычно.
Длина `b"\x00\xff"` равна двум; произвольные байты не обязаны быть UTF-8.

## Запись байтов

Внутри литерала разрешён печатный ASCII, кроме неэкранированных `"` и `\`.
Остальные байты задаются escapes:

| Запись | Значение |
| --- | --- |
| `\0` | 0 |
| `\n`, `\r`, `\t` | 10, 13, 9 |
| `\\`, `\"` | 92, 34 |
| `\xNN` | Один байт, ровно две hex-цифры, 00..ff |

Например, `b" RTSP/1.0\r\n"` содержит протокольную строку с CRLF.
Неизвестные escapes, `\uXXXX`, непосредственно записанные Unicode-символы
и переносы строк отвергаются. Для UTF-8-текста остаётся обычный `Text`-литерал
`"Лиза"`; UTF-8-байты можно задать явно как `b"\xd0\x9b"`.

## Владение и ограничения

Статические байты неизменяемы. `var v=b"PLAY"` разрешает переприсвоить
дескриптор `v`, но не изменять `v[0]`. Копирование дескриптора не копирует
payload; move сохраняет обычную проверку use-after-move.

Backing литерала живёт всё время процесса. Поэтому subview может пережить
локальную привязку исходного дескриптора. Это не продлевает lifetime массива
или Buffer, если view позже переназначен на их память: действуют прежние
консервативные правила объединения loans на ветвлениях и циклах.

Литералы не вводят возвращаемые ссылки: `View` по-прежнему нельзя вернуть
из функции или сохранить в структуре, enum либо массиве. Не добавлены
глобальные переменные, интернирование, concatenation и преобразование
в `[u8;N]`. Если нужны изменяемые/владеющие байты, их явно копируют
в существующий bounded Buffer или String API.

## Приёмка на RTSP

Константы из `rtsp.words` заменены прямыми литералами в RTSP request,
header/SDP lookup и выборе метода. Вместо возврата `can.text.Value`
с массивом на 1024 байта helpers принимают `View<u8>`. Динамические URL,
session и прочие полученные значения сохраняют прежнее bounded хранилище.

Тесты проверяют все 256 значений байта, NUL, пустой литерал, escapes,
передачу аргумента, subview/lifetime и запрет изменения/escape. На O0/O2
проверяется точный бинарный вывод. Отдельный cost-тест проверяет LLVM IR
и assembly: литерал в `probe` передаётся дескриптором без payload allocation,
`memcpy` или `memmove`. Это локальное свойство литерала, а не обещание
отсутствия копий динамического RTSP/WSS-состояния во всём приложении.
