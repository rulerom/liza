# Минимальный I/O — проект контракта

**Статус:** план для 0.0.12–0.0.14. Исполняемое ядро остаётся 0.0.11:
консоль, файловый ввод, текстовые литералы и `: io` пока не реализованы.
`Result`, `match`, readonly views и возврат кода из `main` уже доступны.
Минимальный I/O имеет приоритет перед полноценными строками и динамическими
коллекциями.

## Три уровня

| Уровень | Ответственность |
| --- | --- |
| Язык | Контракты эффектов, владение, порядок вычисления и вызовов |
| Библиотека | Имена и сигнатуры функций консоли/файлов, типы ошибок, правила частичного успеха |
| Платформа | Взаимодействие с ОС, преобразование её ошибок, выполнение контракта ресурса |

`console.write` и `console.println` проектируются как библиотечные функции.
Semantic IR содержит обычный вызов с известной сигнатурой и эффектом.
Специальная инструкция языка `print` не нужна. Компилятору понадобится
описание доверенных внешних функций; произвольный FFI этим не разрешается.
Первый срез может предоставлять фиксированный библиотечный namespace без
полной пользовательской системы модулей.

Переносимость означает общий контракт и модель ошибок, а не одинаковые
файлы, права доступа или результат взаимодействия с окружением на разных ОС.
Поддержку каждой платформы нужно подтвердить отдельно.

## Проверяемые pure и io

Предлагаемый минимальный контракт:

- Функция без аннотации остаётся `pure`, как в текущем ядре.
- `: io` явно разрешает внешние операции и вызов других `io`-функций.
- `pure` может вызывать только `pure`. Запрет действует через любое число
  промежуточных функций, включая рекурсивные группы.
- Контракт проверяется и для статически неисполняемой ветки. Оптимизация
  не служит способом обойти проверку эффектов.
- Локальный `var`, trap и возможное незавершение сами по себе не означают I/O.
- `io` не обещает неблокирующее исполнение. Разделение `io` и `block` появится
  при расширении системы эффектов.

Сейчас парсер принимает `: pure`, а IR помечает все функции чистыми: внешних
операций ещё нет. Перед добавлением консоли аннотация должна сохраняться от
AST до IR, а разрешённость каждого вызова — проверяться по его сигнатуре.
Платформенную функцию нельзя объявить чистой только ради оптимизации.

Внешние действия наблюдаемы, даже если результат вызова не используется.
Оптимизатор сохраняет их порядок относительно друг друга и обязательных
traps: вывод перед trap нельзя удалить или перенести за него. Неисполняемая
ветка ничего не выводит. Аргументы вычисляются в установленном языком порядке.

## Консольный срез 0.0.12

Цель — Hello World и вывод целых чисел без введения динамического `String`.
Литерал текста должен иметь определённое UTF-8 кодирование, неизменяемое
содержимое и явный контракт времени жизни. Нет неявного преобразования
произвольного массива байтов в корректный текст. Функция вывода байтов
работает с длиной, а не ищет завершающий нулевой байт.

До реализации фиксируются тип литерала, escape-последовательности и точные
сигнатуры API. `println` добавляет байт LF; для чисел требуется формат,
независимый от locale. Полноценное форматирование и интерполяция отложены.
Вывод не должен требовать скрытого динамического буфера.

Запись может завершиться ожидаемой ошибкой. Поэтому и консоль возвращает
`Result`, а не превращает отказ вывода в trap. Контракт должен описывать
частичный вывод и число уже записанных байтов: ошибка не откатывает внешний
мир. При разрыве канала требуется проверить, что платформенный механизм
завершения процесса не обходит согласованную обработку через `Result`.

В примере Hello World успех и ошибка вывода должны вести к явно выбранным
кодам возврата из `main`. Новый оператор `exit`, глобальная переменная ошибки
и автоматический вывод произвольного `IoError` для этого не нужны.
Тип успешного результата и политика игнорирования `Result` определяются
вместе с API, до реализации примера.

## Ограниченное чтение файла 0.0.13

Первый файловый API читает в хранилище с заранее известной вместимостью.
Операция не расширяет его автоматически. Это требует отдельного контракта
передачи права заполнения: текущий readonly `View<u8>` такого права не даёт.
Перед кодированием выбирается передача владения буфером с возвратом результата
либо ограниченный исключительный доступ. Общая модель изменяемых views
не должна появляться неявно как побочный эффект файлового API.

Обязательные свойства:

- Пока библиотека заполняет буфер, нет конкурирующего чтения или записи через
  другие представления. После чтения известен доступный инициализированный
  диапазон. Хвост буфера не выдаётся за содержимое файла.
- Результат различает число прочитанных байтов, EOF и отказ окружения.
  Короткое чтение само по себе не означает ни ошибку, ни EOF. API чтения
  целого ограниченного файла продолжает чтение по своему контракту.
- Превышение вместимости обнаруживается явно. Нельзя молча передать парсеру
  усечённый пакет как целый файл. Ровно заполненный буфер ещё не доказывает EOF.
- Нельзя полагаться только на предварительный размер файла: контракт должен
  учитывать изменение файла между проверкой и чтением.
- Если ошибка произошла после частичного чтения, определяется доступность
  полученных байтов и состояние владельца. Неинициализированные байты
  никогда не становятся доступными значениями Liza.

Для этого среза библиотека может открывать и закрывать файл внутри одной
операции. Она отвечает за освобождение на каждом пути возврата и за
определённый приоритет ошибки чтения и ошибки закрытия. Дескриптор не выходит
в пользовательскую программу; `defer` и `?` пока не требуются.

Путь тоже требует контракта. Первая программа может использовать фиксированный
литерал; получение пути из аргументов — отдельный минимальный API.
Политика кодирования путей и непредставимых имён определяется для каждой
поддерживаемой платформы. Динамический `String` не является обязательной
предпосылкой этого среза.

## Ресурсы 0.0.14

Публичный файловый ресурс — move-only значение, не произвольно копируемый
номер дескриптора. Открытие даёт право использования; закрытие потребляет
его. Нужны проверки use-after-close, use-after-move, двойного закрытия,
возвратов из ветвей и выходов из циклов.

До публичного `open/close` необходимо выбрать правило освобождения при раннем
возврате: проверяемое явное закрытие на всех нормальных путях либо определённое
автоматическое освобождение. Само наличие `move` не решает утечки ресурсов.
Политика освобождения при trap задаётся отдельно; trap не считается ожидаемой
ошибкой файловой операции.

Внешняя ошибка возвращается значением `IoError`; она не хранится в доступном
программе неявном глобальном состоянии. Категории ошибок библиотеки и при
необходимости сведения платформы разделяются. Универсальные указатели и
общий доступ к системным дескрипторам не входят в минимальный API.

## Критерии приёмки

Для 0.0.12: прямой и транзитивный запрет I/O из `pure`, сохранение порядка
вывода и traps, точные UTF-8 байты и формат чисел, обработка отказа вывода,
совпадение O0/O2 на поддерживаемых платформах. Проверяется отсутствие
неоговорённых аллокаций в выбранном тракте.

Для 0.0.13: бинарный файл → ограниченный буфер → `View<u8>` → чистый
`parse_rtp` → консольный результат. Ошибка файлового ввода, `ParseError` и
ошибка вывода остаются разными результатами. Пустой файл успешно читается,
после чего RTP-парсер возвращает `TooShort`.

Ожидаемые ошибки не завершают процесс через trap. Размер буфера ограничен,
все ресурсы освобождаются по контракту, передача данных парсеру не копирует
весь пакет. Это проверка конкретного тракта, а не обещание zero-copy внутри
ОС или одинаковой производительности на всех платформах.
