# Milestones Liza

**Текущий рубеж — 0.0.16:** нативные программы для Linux x86-64, macOS ARM64
и Windows x86-64, обновление составных значений, консольный вывод,
файловые ресурсы с владением и проверяемые эффекты.

Milestone означает работающую возможность с определённой семантикой и
проверками. Это не обещание стабильного API или готовности к production.
Даты будущих этапов не назначены: переход определяется критериями готовности.
Подробный порядок работ — в [roadmap](roadmap.md).

## 18 октября 2026 — основание Liza

Исходная цель: отделить смысл вычисления от физического размещения данных,
сохранить определённую семантику и дать контроль над стоимостью операций.
Эта цель остаётся основой решений о типах, владении и эффектах.

## Текущий результат: нативная программа

```liza
fn main() -> u32 : io {
    match console.println("Hello, Liza!") {
        Ok(written) => { return 0 }
        Err(error) => { return 1 }
    }
}
```

Один исходник собирается на каждой из трёх поддержанных host-платформ.
Компилятор написан на Python, но готовой программе Python не нужен.
Язык понижается в LLVM IR напрямую; C используется для платформенной
runtime консоли. Кросс-компиляция пока не реализована.

Этот рубеж включает обработку частичного вывода, закрытого stdout и pipe,
UTF-8 текст, вывод чисел и сохранение обязательных traps. Windows дополнительно
проверяется на Unicode-вывод в консоль и полный 32-битный код завершения.
Объём платформенных проверок различается: POSIX signal-тесты и Windows
handle-тесты проверяют соответствующие реализации одного API.

[Собрать Hello World](getting-started.md) · [Контракт I/O](io-model.md).

## 0.0.13 — первый файловый инструмент

**Реализовано:** `file.read`, буфер 2 КиБ, ошибки через `Result`, пример `rtp_file.liza`.
[Контракт, ограничения и запуск](io-model.md#0013).

Бинарный файл → буфер ограниченной вместимости → `View<u8>` → чистый
RTP-парсер → консольный результат.

Контракт этапа:

- Чтение не увеличивает буфер скрыто; превышение вместимости обнаруживается.
- Доступен только диапазон инициализированных байтов; владение при заполнении определено.
- Ошибки файлового ввода, формата RTP и вывода остаются разными значениями.
- Закрытие вызывается на успешном и ошибочном пути; приоритет ошибок определён.
- Передача заполненного буфера парсеру не копирует весь пакет в выбранном тракте.

## 0.0.14 — файловые ресурсы с владением

**Реализовано:** `File`, `file.open`, чтение чанками и `file.close(move file)`.
Компилятор запрещает копирование, повторное использование и пропущенное
закрытие на нормальном выходе. Пример `file_stream.liza` обрабатывает файлы
больше 2 КиБ, сохраняя фиксированную вместимость одного чанка.
[Контракт ресурсов](io-model.md#0014).

## 0.0.15 — обновление составных значений

**Реализовано:** `var` позволяет обновлять поля структур и элементы массивов,
включая вложенные пути и динамические индексы. Копии независимы, readonly views
блокируют запись, проверки границ сохраняют trap. Индексы и их проверки
предшествуют правой части; ветвления и циклы объединяют целые значения.
Частичных перемещений и mutable views нет.

Пример: `value_updates.liza`. [Полный контракт](core.md#0015).

## 0.0.16 — таблица соединений и стоимость обновления

Функциональный срез: 64/4096 слотов, ID с поколением, `get/add/edit/del`,
вывод слота из обращения при исчерпании поколений, независимые копии.
Новых конструкций языка нет. Чтение не материализует всю таблицу.
В проверенном тракте единственного владельца `edit` не копирует таблицу,
включая обратное ребро цикла. Проверка стоимости охватывает 64/4096/16384 слота;
живые снимки сохраняют независимость.
[Контракт и результаты](connection-table.md).

## Дальнейшие рубежи

Полноценные строки UTF-8, динамические
коллекции и модули; затем расширенная модель эффектов, FFI, задачи и сеть.
Таблица соединений и автомат узла кластера будут проверять модель на
[эталонных задачах](reference-programs.md).

Контролируемая стоимость, переносимость семантики и возможность self-hosting
остаются направлениями развития. Они требуют отдельных подтверждений
по мере роста языка.
