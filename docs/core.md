# Исполняемое ядро 0.0.22

Это спецификация текущего прототипа, не полного языка Liza.

## Типы и литералы

Доступны `u8`, `u16`, `u32`, `u64`, `i8`, `i16`, `i32`, `i64` и `bool`.
Для N бит unsigned имеет диапазон 0…2^N−1, signed — −2^(N−1)…2^(N−1)−1.
Знаковые битовые операции определены через дополнение до двух.
`bool` содержит только `true` и `false`; неявных преобразований между типами нет.

Литерал хранится компилятором как математическое целое и получает тип из
аннотации привязки, результата функции, параметра вызова или типизированного
операнда. Контекст распространяется через скобки и арифметические операции
в обе стороны. Это вывод типов, а не изменение порядка исполнения.
Если контекста нет, выбирается `u32`, независимо от величины литерала.
Литерал вне диапазона выбранного типа — ошибка компиляции. Исключение из
выбора машинного типа для литерала — непосредственный аргумент явного
преобразования: его правила описаны ниже.

```text
fn offset(x: i16) -> i16 {
    y = (1 + 2) + x       // все операнды имеют тип i16
    return y
}

fn main() -> u32 {
    minimum: i8 = -128
    positive: u8 = 42
    if minimum < 0 && positive == 42 { return 0 }
    return 1
}
```

Минус непосредственно перед числовым литералом учитывается до проверки
диапазона: `-128` допустим для `i8`. Унарный минус перед выражением требует
знакового типа и проверяет переполнение: `-MIN` вызывает trap.
`-(128)` в контексте `i8` отклоняется, поскольку внутренний литерал 128
не представим; для минимального значения используется запись `-128`.
Отрицательный литерал без знакового контекста отклоняется как непредставимый
в `u32`. Десятичные и `0x`-литералы подчиняются одинаковым правилам диапазона.

## Синтаксис

Ниже базовый фрагмент грамматики. Правила модулей и параметров типов
дополнены в разделах [модулей](modules.md) и [generics](generics.md).

```text
program   := (function | structure | enumeration)*
enumeration := "enum" name "{" alternative (separator alternative)* "}"
alternative := name ("(" type ")")?
match_statement := "match" expression "{" (pattern "=>" block)* "}"
pattern := (name ".")? name ("(" name ")")?
structure := "struct" name "{" fields? "}"
field     := name ":" type
function  := "fn" name "(" parameters? ")" "->" type (":" effects)? block
effects   := "pure" | effect ("," effect)*
effect    := "io" | "alloc"
type      := "Text" | "u8" | "u16" | "u32" | "u64" | "i8" | "i16" | "i32" | "i64" | "bool" | structure_name | enum_name | "Option<" type ">" | "Result<" type "," type ">" | "[" type ";" length "]" | "View" "<" type ">"
parameters := name ":" type ("," name ":" type)*
block     := "{" statements "}"
statement := ("var")? name (":" type)? "=" expression
           | "return" expression | conditional | "while" expression block
           | "break" | "continue" | match_statement | block
conditional := "if" expression block ("else" (block | conditional))?
expression := literal | "true" | "false" | name | name "(" arguments? ")"
            | "(" expression ")" | unary expression | expression binary expression
            | expression "." name | "[" arguments? "]" | expression "[" expression "]"
            | "view" name "[" expression ".." expression "]"
            | integer_type ("." ("wrap" | "saturate"))? "(" expression ")"
unary     := "!" | "~" | "-" | "copy" | "move"
binary    := "+" | "-" | "*" | "/" | "%" | "+%" | "-%" | "*%" | "+|" | "-|" | "*|"
            | "==" | "!=" | "<" | "<=" | ">" | ">="
            | "&" | "|" | "^" | "<<" | ">>" | "&&" | "||"
```

Привязки, `return`, `break` и `continue` разделяются newline или `;`, перед `}` разделитель
необязателен. После блока `if/else` или `while` разделитель также необязателен.
`else` допускается на той же или следующей строке; `;` перед `else` недопустим.
Заголовки функций и выражения пока однострочные. Открывающая `{` следует
на той же строке, что заголовок функции, условие или `else`.
Комментарий `//` продолжается до конца строки.

`integer_type` — один из восьми целых типов; `bool` не допускает преобразований.
`wrap` и `saturate` обозначают режим после имени типа, а не методы объектов.

Идентификаторы ASCII: `[A-Za-z_][A-Za-z_0-9]*`. Имена встроенных типов, `fn`, `return`,
`pure`, `io`, `Text`, `enum`, `match`, `Option`, `Result`, `Some`, `None`, `Ok`, `Err`, `true`, `false`, `if`, `else`, `var`, `while`, `break`, `continue`, `copy`, `move`, `struct`, `view`, `View` зарезервированы.

## Имена, функции и ветвления

`x = expr` создаёт неизменяемую привязку, если имя x ещё не видно.
`var x = expr` создаёт изменяемую локальную привязку; инициализатор обязателен.
В обоих случаях допустима аннотация: `x: u8 = 10`, `var x: u8 = 10`.
Тип выбирается при объявлении и не меняется при присваивании.

Если x уже видно, `x = expr` — присваивание, допустимое только для `var`.
Правая часть вычисляется один раз, используя прежние значения, затем имя
связывается с результатом. Целевой тип задаёт контекст литералам правой части;
типизированное значение другого типа требует явного преобразования.
Повторная аннотация `x: T = expr` считается переобъявлением и запрещена.
Составных присваиваний (`+=` и других) пока нет.

`var` даёт право заменить значение имени, а не изменить объект или ячейку
памяти с идентичностью. Например:

```text
var x: u8 = 10
snapshot = x
x = x + 1
// x == 11, snapshot == 10
```

**Области видимости.** Имя доступно только после объявления, в том числе
`var x = x + 1` без ранее видимого x запрещено. Параметры функций неизменяемы.
Переобъявление любого видимого имени, включая имя внешней области, запрещено.
Поэтому `var x` во вложенной ветке не может затенить внешний x; обычное `x =`
обновит внешнюю `var`, а для внешней неизменяемой привязки даст ошибку.

Ветки `if` имеют отдельные области. Их локальные имена не видны после ветки
или в соседней ветке. Новое имя можно независимо использовать в соседних
ветках либо после завершения его области. Обновления внешних `var` сохраняются
после выбранной ветки. Если ветка не присвоила новое значение, сохраняется
предыдущее. Если ветка завершилась через `return`, её значения не участвуют
в продолжении функции. Все ветки проверяются статически.

`var` разрешена только для локальных привязок внутри тела функции, ветки или цикла.
Глобальные переменные, отдельные блоки-инструкции,
heap, ссылки и владение этой конструкцией не вводятся.

Функции видимы во всём модуле, включая forward calls. Рекурсия разрешена,
завершение не доказывается. Имена функций и локальных значений находятся
в разных пространствах: `f(...)` ищет функцию или конструктор структуры, простое `f` — значение.
Типы параметров и результата обязательны.

`if` — инструкция. Условие вычисляется один раз и имеет тип `bool`;
выполняется только выбранная ветка. `else` необязательно; доступны вложенные
ветвления и `else if`. Каждый завершающийся путь функции должен закончиться `return`
объявленного типа. Возврат из обеих веток достаточен; код после него отклоняется.
Проверка структурная: `if true {return 1}` без `else` требует последующего
возврата. Обе ветки проверяются статически, даже если условие известно заранее.

Ровно одна `main() -> u32` без параметров обязательна. Без аннотации функция
имеет контракт `pure`; `: io` разрешает внешние операции, `: alloc` — операции
выделения и освобождения хранилища. Эффекты можно объединить: `: io, alloc`.
Чистая функция не может вызвать функцию с любым из этих эффектов, даже
в неисполняемой ветви. Локальное присваивание не является внешним эффектом.
Контракты описаны в [минимальном I/O](io-model.md) и [модели регионов](regions.md).

## Структуры-значения

`struct` объявляет номинальный тип на уровне модуля. Два разных имени типов
не совместимы даже при одинаковых полях. Имена структур уникальны и не могут
совпадать с именами функций. Объявления типов и функций видны во всём модуле,
включая ссылки вперёд; локальное имя не скрывает конструктор в записи `T(...)`.

```text
struct Point {
    x: i32
    y: i32
}

struct Segment {
    start: Point
    end: Point
}

fn shifted(p: Point) -> Point {
    return Point(p.x + 1, p.y)
}
```

У каждого поля обязательны уникальное в структуре имя и тип. Поля разделяются
новой строкой, `;` или `,`; после последнего поля разделитель необязателен.
Тип поля — скаляр, фиксированный массив или другая структура. Пустая структура `struct Empty {}`
допустима. Прямые и косвенные циклы вложения по значению запрещены, включая
неиспользуемые объявления. Указателей и рекурсивных контейнеров здесь нет.

Конструктор `Point(10, 20)` принимает ровно по одному аргументу на поле,
в порядке объявления. Аргументы вычисляются слева направо и получают контекст
типа своего поля. Пропусков, значений по умолчанию и именованных аргументов
пока нет. Непредставимый литерал или несовпадающий тип — ошибка компиляции.
Trap или бесконечное выполнение аргумента нельзя устранить, даже если
конструируемое значение или соответствующее поле не используется.

`p.x` читает значение поля; `segment.start.x` читает вложенное поле.
Допустимы поля временного результата: `shifted(p).x`. Доступ к полю имеет
приоритет выше унарных операций. Чтение поля создаёт логически независимое
значение, не ссылку на часть владельца. Неизвестное поле и доступ к полю
скаляра отклоняются статически.

```text
var p = Point(10, 20)
snapshot = copy p
p = Point(p.x + 1, p.y)
// snapshot.x == 10, p.x == 11
```

`var` разрешает заменить структуру целиком или обновить поле: `p.x = 11`.
Тип структуры и поля сохраняется. Частичного перемещения нет: `move p.x` отклоняется.
`(move p).x` перемещает всю привязку p, затем извлекает поле из полученного
значения. После этого p недоступна, пока изменяемая привязка не восстановлена.
Обычная передача структуры функции и чтение поля сохраняют доступность источника;
явный `move` действует на всю исходную привязку.

Арифметика, преобразования и сравнение `==`/`!=` структур не определены;
программа работает с отдельными полями. Методов, наследования, автоматического
освобождения ресурсов и изменяемых объектов эта версия не вводит.

Порядок полей задаёт порядок аргументов конструктора, но не обещает смещения
в памяти, padding, выравнивание, endianess или совместимость с C ABI.
Сериализация должна определяться отдельными операциями. Скрытых heap-аллокаций
и обязательного подсчёта ссылок для структур нет; стоимость физической передачи
может зависеть от размера и оптимизаций. Копирование и перемещение не обещают O(1).

## Фиксированные массивы и readonly views

Тип `[T; N]` содержит ровно N элементов одного типа T. Длина — десятичный
или hex-литерал в диапазоне `u32`, часть типа, не runtime-выражение.
Элементом может быть скаляр, структура или массив; views в массивах и структурах
запрещены. Свойства копирования массива следуют из свойств элемента.

```text
data: [u8; 4] = [10, 20, 30, 40]
part = view data[1..3]
x = part[0] // 20
```

Литерал массива вычисляет элементы слева направо, ровно один раз. Тип элемента
выводится из контекста или типизированных элементов. Без такого контекста
целые литералы получают `u32`. Длина литерала обязана совпадать с аннотацией.
Пустой массив допустим: `empty: [u8; 0] = []`; без контекста `empty = []`
отклоняется. Вложенные массивы и массивы структур поддерживаются.

`data[index]` вычисляет основание, затем индекс типа `u32` и проверяет
`index < N`. Неявного преобразования индекса нет. Некорректный индекс,
включая константный, вызывает runtime trap, даже если результат не используется.
Любая индексация пустого массива вызывает trap. Неисполняемая ветка не обращается
к массиву. Индексация возвращает значение элемента, а не копию всего массива.
Для большого составного элемента логическое копирование может быть дорогим.

Массив можно передавать и возвращать по значению, копировать и перемещать.
`var` разрешает заменить весь массив или отдельный элемент с сохранением типа.
Частичный `move` запрещён. Копии логически независимы.

**Создание view.** `view owner[start..end]` принимает только доступную привязку
массива. Источник не может быть временным выражением, полем структуры, элементом
массива или другим view. Диапазон полуоткрытый; оба конца имеют тип `u32`.
Владелец заимствуется до вычисления начала и конца, которые вычисляются
слева направо. Переместить владельца при вычислении границ нельзя.

Проверяется `start ≤ end ≤ N`. После успешной проверки длина равна `end - start`;
промежуточных сумм с возможным переполнением нет. Полный и пустой диапазоны
допустимы, включая `[N..N]`. Некорректный диапазон вызывает trap при создании,
даже если view далее не используется.

`View<T>` даёт readonly-доступ к элементам владельца без копирования содержимого.
Чтение `part[index]` проверяет `index < end - start`, затем возвращает значение
элемента. Любое чтение пустого view вызывает trap. View нельзя преобразовать
в адрес; ни адресная арифметика, ни изменение через view не доступны.

**Лексические заимствования.** Пока действует заимствование, запрещены `move`
владельца и любое повторное присваивание ему. Читать и копировать владельца
разрешено; копия является независимым владельцем и не наследует его заимствования.
Несколько readonly views одного массива допустимы.

Заимствование сохраняется до конца блока создания view, даже после последнего
чтения, перемещения или переприсваивания самого view. Для inline-view в аргументе
вызова действует то же консервативное правило. Выход из блока через `break`,
`continue` или `return` завершает его локальные заимствования. При следующей
итерации тела цикла локальные привязки и заимствования создаются заново.
View в условии `if`/`while` относится к окружающему блоку.

```text
var data = [1, 2]
if true {
    part = view data[0..1]
    value = part[0]
}
other = move data // область part завершена
```

View можно объявлять локально, копировать, перемещать и передавать параметром
`View<T>`. Параметр — временный readonly-доступ на протяжении вызова, без нового
владельца. Вызов не снимает ограничений исходного заимствования у вызывающего.
Возвращать views и сохранять их внутри составных значений запрещено.

При присваивании view внешней локальной `var` заимствование продлевается до
области этой привязки. Владелец должен быть объявлен в той же или внешней области;
иначе это ошибка выхода за время жизни владельца. Такой анализ консервативен:
возможные заимствования внешней области объединяются при ветвлениях и циклах,
без доказательства значений условий. Переприсваивание view не сокращает уже
начатых заимствований. Полноценные параметры времён жизни не вводятся.

## Копирование и перемещение

Операции работают со скалярами, массивами, структурами-значениями и views.
Копирование view копирует только право доступа с тем же владельцем и временем жизни.
Свойства `copyable` (допустимо явное копирование) и `implicit_copy`
(допустимо неявное копирование) различаются; у всех этих типов оба равны
`true`. Размер и физическое размещение значения не меняют свойства типа.
Для структуры каждое свойство выводится как конъюнкция свойств её полей,
рекурсивно. Поэтому все структуры текущего ядра тоже допускают явное
и неявное копирование. Пользовательских объявлений свойств пока нет.
Исключение — встроенный ресурс `File` и содержащие его варианты: они move-only,
не допускают `copy` и требуют передачи или закрытия на нормальном выходе.

`copy expr` вычисляет выражение один раз и создаёт независимое логическое
значение того же типа. Само копирование не делает исходную привязку
недоступной. Контекст типа проходит через `copy`: `x: u8 = copy 42` допустимо.
Trap при вычислении аргумента сохраняется даже при неиспользуемой копии.

`move name` возвращает текущее значение привязки и делает его недоступным
для последующих чтений, включая `copy` и повторный `move`. Это действует
и для скаляров, и для параметров функций. Операндом служит имя, возможно
в скобках; `move (x + 1)` и `move 42` запрещены. Эти префиксные операции
имеют приоритет остальных унарных операций: `move x + 1` — `(move x) + 1`.

```text
var x: u32 = 10
snapshot = copy x
transferred = move x
x = 20
// snapshot == 10, transferred == 10, x == 20
```

У `var` присваивание восстанавливает доступность с прежним типом. Правая
часть вычисляется до восстановления: после перемещения `x = x + 1`
недопустимо. `x = move x` допустимо, если x доступна до присваивания.
Неизменяемую привязку и параметр нельзя восстановить присваиванием.
Перемещение не освобождает имя для повторного объявления или затенения.

Для скаляров, массивов и структур обычное чтение, присваивание, передача аргумента и возврат
неявно копируют значение. `f(x)` сохраняет доступность x у вызывающего;
`f(move x)` её прекращает. Параметр функции является отдельной привязкой.
`return move x` возвращает значение, завершая путь. Аргументы и операнды
проверяются в порядке вычисления слева направо: `f(x, move x)` допустимо,
`f(move x, x)` — ошибка. `copy (move x)` не отменяет внутреннего перемещения.

После объединения путей читать имя можно, только если оно доступно на
каждом продолжающемся пути. Пути через `return` или без выхода не участвуют
в объединении. `break` передаёт состояние доступности на выход цикла,
`continue` и конец тела — к следующей проверке условия. Проверка учитывает
все повторения до устойчивого состояния; восстановление должно предшествовать
следующему чтению. Локальные привязки тела создаются заново на каждой итерации.

Анализ консервативный, без доказательства значений условий. Обе ветки `if`
и оба пути `&&`/`||` участвуют в проверке даже при литеральном условии.
Тело `while false` также проверяется с обратными переходами. Поэтому
`x = 1; if false { y = move x }; return x` отклоняется. Это статическое
ограничение; при исполнении невыбранные ветки по-прежнему не вычисляются.

Независимость копии — семантический контракт, не обещание обязательной
физической копии. `move` не создаёт дополнительного независимого владельца,
но не гарантирует O(1): встроенные составные значения могут требовать
переноса байтов. Здесь не вводятся heap, деструкторы, подсчёт ссылок,
copy-on-write, заимствования или гарантии стоимости для будущих типов.

## Циклы и завершение

`while condition { ... }` проверяет условие типа `bool` перед каждой итерацией.
При `false` тело не выполняется. `continue` переходит к следующей проверке
условия ближайшего цикла; `break` выходит из ближайшего цикла. `return`
завершает всю функцию. Меток и значений у `break`/`continue` нет;
вне цикла эти инструкции запрещены.

```text
fn gcd(a: u32, b: u32) -> u32 {
    var x = a
    var y = b
    while y != 0 {
        remainder = x % y
        x = y
        y = remainder
    }
    return x
}
```

Тело имеет отдельную область видимости на каждой итерации. Его локальные
имена не видны в условии и после цикла; затенение внешних имён запрещено.
Обновления внешних `var` сохраняются при следующей итерации и выходе,
в том числе через `continue` и `break`. Тело проверяется статически даже
при условии `false`. Код после безусловного переноса управления отклоняется.

Бесконечное выполнение допустимо. Оптимизация не вправе заменить его
возвратом или trap либо перенести последующий trap перед бесконечным циклом.
Чистота не обещает завершения; обязательного требования прогресса нет.

Проверка возврата структурная. `while true` без структурного пути через
`break` может завершать тело функции без `return`; код после такого цикла
недостижим. Скобки вокруг `true` этого не меняют. Для других условий
компилятор допускает выход по `false` и требует возврат на продолжающемся
пути. Даже `if false { break }` создаёт структурный выход; `break` во
вложенном цикле не создаёт выхода из внешнего. Произвольные условия
на истинность и завершение компилятор не доказывает.

## Порядок вычислений и приоритеты

Операнды и аргументы вычисляются слева направо, инструкции — в порядке исходника.
`&&` вычисляет правую часть только если левая истинна; `||` — только если ложна.
Обе части имеют тип `bool` и всегда проверяются статически.

Приоритеты от высокого к низкому:

| Операции | Операнды | Результат |
| --- | --- | --- |
| `.field` | Структура | Тип поля |
| `copy`, `move` | Значение / имя привязки соответственно | Тип операнда |
| `!`, `~`, унарный `-` | bool / целое / знаковое целое соответственно | Тип операнда |
| `*`, `*%`, `*\|`, `/`, `%` | Одинаковый целый тип | Тот же тип |
| `+`, `-`, `+%`, `-%`, `+\|`, `-\|` | Одинаковый целый тип | Тот же тип |
| `<<`, `>>` | Целое слева, `u32` справа | Тип слева |
| `<`, `<=`, `>`, `>=` | Одинаковый целый тип | bool |
| `==`, `!=` | Одинаковый скалярный тип | bool |
| `&` | Одинаковый целый тип | Тот же тип |
| `^` | Одинаковый целый тип | Тот же тип |
| `\|` | Одинаковый целый тип | Тот же тип |
| `&&` | bool, bool | bool |
| `\|\|` | bool, bool | bool |

Бинарные операции одного приоритета ассоциируются слева. Для проверки маски
нужны скобки: `(flags & mask) != 0`. Числовые операнды сравнения не получают
тип bool из результата: их тип выводится независимо, либо выбирается `u32`.
Сравнения учитывают знаковость: для `i8` −1 < 1, для `u8` 255 > 1.

## Явные преобразования

Для любого целого типа T доступны:

| Запись | Семантика |
| --- | --- |
| `T(x)` | Значение сохраняется, если представимо в T; иначе trap |
| `T.wrap(x)` | Остаток по модулю 2^N, затем интерпретация N бит в T |
| `T.saturate(x)` | Ограничение математического значения границами T |

Для signed-результата wrapping: если остаток r ≥ 2^(N−1), результат r−2^N.
Это действует при сужении, расширении и смене знаковости. Например,
`u64.wrap(i8(-1))` даёт 18446744073709551615, а `u64(i8(-1))` вызывает trap.
У `T.wrap` и `T.saturate` нет собственных runtime traps, но вычисление аргумента
может вызвать trap. Аргумент вычисляется ровно один раз, до преобразования.

Непосредственный литерал (включая отрицательный и окружённый скобками)
остаётся математическим целым произвольной точности. `u8(300)` — ошибка
компиляции, `u8.wrap(300)` — 44, `i8.wrap(-129)` — 127,
`u8.saturate(-10)` — 0. Непредставимый checked-литерал отклоняется и в мёртвой
ветке. Для литерального преобразования нет runtime-вычисления bigint.

Обычное выражение внутри преобразования типизируется независимо от T:
сначала действуют его собственные контексты и default `u32`, затем преобразование.
`u8(250 + 10)` вызывает runtime trap; `u8.wrap(250 + 10)` возвращает 4.
Если `x: u8 = 255`, то `u8.wrap(x + 1)` и `u8.saturate(x + 1)` вызывают trap
на сложении. Запись `i64(-1 + 0)` отклоняется: отрицательный литерал внутри
выражения не помещается в default `u32`; используйте `i64(-1) + 0`.
При вложении `u8(i16(300))` внутреннее преобразование уже даёт типизированное
значение, поэтому внешнее вызывает runtime trap, а не ошибку диапазона литерала.

`as`, преобразования `bool` и неявные преобразования отсутствуют.

## Арифметика и биты

`+`, `-`, `*` и унарное отрицание signed проверяют представимость результата;
при переполнении выполняется trap. `+%`, `-%`, `*%` считают по модулю 2^N;
для signed результат интерпретируется в дополнительном коде.
Промежуточное переполнение не исчезает при свёртке выражения: `(x+1)-1`
вызывает trap для MAX даже при неиспользуемом результате.

`+|`, `-|`, `*|` вычисляют математический результат и ограничивают его
диапазоном исходного типа. Оба операнда имеют одинаковый целый тип;
приоритеты и ассоциативность совпадают с обычными `+`, `-`, `*`.
Ограничение выполняется после каждой операции: для `x: u8 = 250`
`(x +| 10) -| 10` равно 245. Замена на `x` недопустима.
Насыщение не подавляет trap при вычислении операндов.

`/` и `%` требуют одинакового целого типа операндов и возвращают тот же тип.
Частное округляется к нулю; ненулевой остаток имеет знак делимого.
Например, для `i32`: `-7 / 3 == -2`, `-7 % 3 == -1`, `7 % -3 == 1`.
Математически `a = q*b + r`, где q — частное, r — остаток.
Обе операции вызывают trap при нулевом делителе. Для signed `MIN / -1`
вызывает trap, а `MIN % -1` возвращает ноль. Остаток вычисляется самостоятельно,
без промежуточного checked-частного. Эти правила действуют и для констант:
`1 / 0` типизируется, но вызывает trap только при исполнении.

`&`, `|`, `^`, `~` работают с N битами без арифметического переполнения.
`<<` отбрасывает выходящие биты, затем интерпретирует результат в исходном типе.
`>>` заполняет старшие биты нулями для unsigned и знаковым битом для signed.
Счётчик — `u32`; `n >= N` вызывает trap до машинного сдвига. Его значение
не маскируется и не усекается перед проверкой. Signed-счётчик и отрицательный
литерал счётчика отклоняются. Ноль — допустимый сдвиг.

Trap — наблюдаемое аварийное завершение. Оптимизация должна сохранять
наблюдаемый результат, включая обязательные trap и отсутствие исполнения
невыбранных ветвей/операндов. Перенос проверки допускается только с доказательством
эквивалентности. Конкретный сигнал и сообщение не гарантируются.
Исчерпание памяти/стека не моделируется ядром. Чистота не доказывает отсутствие trap.

`main` передаёт результат host ABI как код завершения. POSIX shell видит
младшие 8 бит. Для проверки значений шире 8 бит нужно сравнение полных значений,
а не только кода завершения процесса.

## Liza IR и backend

IR версии 19 содержит типизированные значения, параметры, базовые блоки,
`return`, `branch`, `jump` и `phi` для результатов короткого замыкания.
`copy` и `move` остаются самостоятельными типизированными операциями.
В JSON `type_properties` явно задаёт `copyable` и `implicit_copy`.
Проверка доступности привязок выполняется по исходному управлению потоком
после типизации и построения IR, до передачи проверенного модуля backend.
Внешний неподтверждённый IR не принимается. Для скаляров и структур backend представляет
`copy`/`move` как тождественное значение, не создавая адресуемую переменную.

В `structures` находятся номинальные определения с именами и типами полей.
`struct.construct` создаёт значение из аргументов в порядке полей,
`struct.field` содержит `source_type` и `field_name`.
`struct.update` возвращает агрегат с заменённым полем. Смещений и адресов
в этих операциях нет. Структуры участвуют в параметрах, результатах и `phi`
как обычные значения. Для небольших структур LLVM backend использует
[`insertvalue`/`extractvalue`](https://llvm.org/docs/LangRef.html#aggregate-operations);
крупные значения могут храниться в памяти backend. Это стратегия реализации,
а не определение семантики Liza и не введение адресуемых полей в язык.

`array.construct`, `array.read`, `array.update`, `view.create`, `view.read` задают логические
операции. Доступ и создание диапазона имеют `bounds_policy: trap` и `may_trap`.
`view.create` хранит SSA-значение владельца, начало, конец и имя исходной привязки;
это связь с владельцем, не пара «адрес/длина». Время жизни проверяется до backend.
Потенциальные traps распространяются через вызовы так же, как арифметические.

Backend может материализовать SSA-значение массива в локальном хранилище один раз
на его вычисление и представлять view адресом и длиной. Его чтение проверяет
границы до загрузки элемента; повторное создание view того же SSA-значения
не требует повторного сохранения массива. В Semantic IR адресов нет.
Это не универсальная гарантия отсутствия физических копий для всех программ.

Типы сохраняют ширину и знаковость. Арифметическая политика задаётся `overflow`,
политика неправильного счётчика — `shift_policy: trap`.
`div` и `rem` имеют `division_policy: trap`: нулевой делитель вызывает trap;
для signed `div` дополнительно проверяется `MIN / -1`. Частное округляется
к нулю, signed `rem` возвращает ноль для `MIN % -1`.

`convert.checked`, `convert.wrap`, `convert.saturate` содержат `source_type`
и целевой `type`. Для непосредственного литерала `source_type: integer` —
математическая константа, существующая только на этапе компиляции; для
остальных аргументов это фиксированный целый тип. Насыщаемые `add/sub/mul`
имеют `overflow: saturate`. Преобразование и насыщаемая арифметика различаются.

`may_trap` у операций и функций распространяется через вызовы, включая рекурсию.
Это консервативная оценка: она не доказывает достижимость trap, завершение функции
или отсутствие исчерпания стека. После изменения IR сведения пересчитываются.
Порядок операций и граф блоков сохраняют порядок потенциальных trap.
Перезапись привязки не позволяет удалить обязательное вычисление:
`var x: u8 = 255; x = x + 1; x = 0` вызывает trap на сложении.

Локальная изменяемость понижается непосредственно в SSA: каждое присваивание
выбирает новое значение имени. После `if` для изменённых внешних привязок
создаются `phi` со значениями только от продолжающих выполнение ветвей.
При единственном продолжающем пути либо одинаковом SSA-значении на всех
путях новый `phi` не нужен. Локальные имена ветки за её границы не выходят.
IR не содержит адресуемых локальных переменных; для реализации `var`
backend не вводит `alloca/load/store` для скаляров и структур без доступа
к массивам. Для динамической индексации и views массив может получить временное
размещение в памяти; это не делает привязку адресуемой на уровне Liza. Размещение значений в регистрах или
на стеке после машинной компиляции не является частью семантики языка.

Заголовок цикла объединяет начальные значения и значения обратных переходов
через `phi`; выход объединяет пути ложного условия и `break`. `continue`
передаёт текущие значения в заголовок. Недостижимая зарезервированная цель
выхода имеет терминатор `unreachable`, без входящих рёбер.

У функций явно задан `termination_contract: may_diverge`: это отсутствие
гарантии завершения, а не утверждение, что каждая функция бесконечна.
Backend не добавляет без доказательства `mustprogress`, `willreturn` или
`llvm.loop.mustprogress`, позволяющие предполагать завершение.

Проверки типов, имён, диапазонов и возврата выполняются до backend.
JSON доступен через `emit-ir`; формат нестабилен, внешнего ввода IR пока нет.
LLVM backend использует i1 для bool и iN для N-битных целых, signed/unsigned
сравнения и overflow intrinsics, обычную модульную арифметику без `nsw/nuw`,
условный переход к trap перед сдвигом. Проверка счётчика остаётся 32-битной,
даже если сдвигаемое значение уже. Деление проверяет ноль и signed-переполнение
до LLVM-инструкции. Для signed-остатка делитель −1 заменяется на +1 до `srem`,
сохраняя нулевой результат и исключая неопределённый случай `MIN % -1`.
Преобразования временно используют расширенное целое для математической
проверки диапазона или насыщения. Насыщаемая арифметика выполняется в ширине,
достаточной для точного результата, затем ограничивается и сужается.
Эти промежуточные типы — детали backend, не типы языка. Оптимизацией занимается
Clang/LLVM; оптимальность этой реализации пока не гарантируется.

## Ещё не реализовано

Динамические массивы, строки, изменяемые объекты, `for`, запись файлов и пользовательские ресурсные типы. Платформозависимые целые,
floating point, SIMD и пользовательские числовые типы не входят в текущее ядро.

## Варианты, Option, Result и match (0.0.11)

`enum` объявляет номинальный тип с непустым набором альтернатив. Альтернатива
содержит ноль или одно значение; несколько полей объединяются в структуру.
Рекурсивные типы по значению запрещены, в том числе через массив или `Option`.

```liza
enum Error { Missing; Invalid(u32) }
fn read(ok:bool)->Result<u32,Error> {
    if ok { return Ok(42) }
    return Err(Error.Missing)
}
fn main()->u32 {
    match read(true) {
        Ok(value) => { return value }
        Err(error) => {
            match error {
                Error.Missing => { return 0 }
                Error.Invalid(code) => { return code }
            }
        }
    }
}
```

Встроенный `Option<T>` имеет `Some(T)` и `None`, `Result<T,E>` — `Ok(T)` и
`Err(E)`. Это встроенные параметризованные типы; пользовательские generic-функции
и структуры описаны в [контракте generics](generics.md). Конструктор получает тип payload из контекста. `Some(1)` выводит
`Option<u32>`, а для `None`, `Ok` и `Err` требуется достаточный контекст
аннотации, параметра или результата функции. В аннотации перед `=` нужен
пробел: `x:Option<u8> = None`.

`match` — инструкция, не выражение. Discriminant вычисляется ровно один раз,
затем выполняется только выбранная ветка. Все альтернативы должны быть
перечислены ровно один раз. Для пользовательских типов используется
`Type.Alternative`; для встроенных — `Some`, `None`, `Ok`, `Err`.
Payload привязывается локально в ветке; `_` позволяет проигнорировать только
нересурсное значение.
Затенение, guards, wildcard-ветки и вложенные patterns пока запрещены;
вложенный `match` разрешён. Доступ к payload вне сопоставления невозможен.

Свойства `copyable` и `implicit_copy` выводятся из всех payload без порога
размера. `match x` копирует логическое значение только для copyable-варианта; `match move x` делает исходную
привязку недоступной на всех путях. Восстановление `var` разрешено присваиванием.
Объединение состояний учитывает только продолжающиеся ветки, включая циклы,
`break`, `continue` и `return`. Payload не может содержать `View`, даже вложенно:
вариант не предоставляет способ сохранить или вернуть заимствование.

В Semantic IR сохраняются `variant.construct`, `variant.tag`,
`variant.payload` и терминатор `switch`; payload извлекается в выбранном блоке.
Создание варианта не выделяет heap. В текущем LLVM backend используется тег
и отдельный слот каждой альтернативы, а не компактный union. Неактивные слоты
инициализируются нулями. Это ограничение реализации: размер и стоимость
передачи могут превышать размер крупнейшего payload; дешёвые копии не обещаны.

## Длина последовательности

`array.len` и `view.len` возвращают `u32`. Для массива это длина типа, для view —
длина выбранного диапазона. Пустая последовательность имеет длину ноль.
Выражение слева вычисляется прежде чтения длины: `.len` не отменяет его traps
и не разрешает использование перемещённой привязки.

## RTP с ожидаемыми ошибками

`examples/rtp_result.liza` возвращает `Result<RtpHeader,ParseError>`.
Проверки следуют порядку: минимум 12 байтов, версия 2, длина списка CSRC,
заголовок и длина расширения, padding. Первая ошибка определяет альтернативу.
Padding включает последний байт со счётчиком и не может превышать оставшуюся
после заголовка длину. Нулевая полезная нагрузка допускается.
Расширение учитывается в 32-битных словах без его четырёхбайтового заголовка.
Эти правила основаны на [RFC 3550, разделах 5.1 и 5.3.1](https://datatracker.ietf.org/doc/html/rfc3550#section-5.1).

Парсер возвращает поля и смещение/длину payload, не возвращает view. Он не
интерпретирует профили расширений, содержимое payload, RTCP или состояние сессии.
Некорректные байты дают `Err`; trap остаётся нарушением контракта вычисления,
а не обычной ошибкой разбора. Runtime-тесты сравнивают результат с независимым
эталоном при O0/O2. Анализ выбранного O2 тракта проверяет чтения входного
буфера без его материализации; машинные расходы возврата структуры допустимы.

## Текст и консоль 0.0.12

`Text` — неизменяемый UTF-8 литерал со статическим временем жизни.
`text.len` возвращает число байтов как `u32`. `copy` не копирует содержимое,
`move` прекращает доступ через исходную привязку. Возврат `Text` безопасен;
это не разрешает возвращать заимствованный `View`. Динамические строки,
индексация текста и конкатенация ещё не реализованы.

Консоль — библиотечные `console.write`, `console.println`,
`console.write_bytes`, `console.print_u64`, `console.print_i64` с эффектом `io`.
Они возвращают `Result<u64,IoFailure>`. [Сигнатуры, ошибки и escapes](io-model.md)
определяют точный контракт. `examples/hello.liza` обрабатывает результат вывода
и возвращает код завершения.

Semantic IR версии 19 содержит `text.literal`, внешние сигнатуры и
`effect_contract` у вызова. Вывод представлен обычным `call`; его нельзя
устранить из-за неиспользуемого результата или перенести через обязательный
trap с изменением наблюдаемого поведения. Имена с префиксом `__liza_`
зарезервированы для реализации. Linux/macOS/Windows runtime подключается при сборке;
Пользовательский FFI пока не поддерживается.

## Файловые ресурсы 0.0.14

`File` — непрозрачный move-only тип. Свойства `copyable=false` и
`implicit_copy=false` распространяются на содержащие его варианты.
На нормальных выходах компилятор проверяет обязательную передачу или закрытие.
Заимствование на время `file.read_chunk` записывается в Semantic IR как
режим параметра `borrow`; обычные параметры имеют режим `value` и получают
владение при передаче ресурса. Версия формата IR — 14.

[API, области действия и поведение при trap](io-model.md#0014).


## Обновление составных значений 0.0.15

```text
struct Point { x: u32, y: u32 }

fn main() -> u32 {
    var points = [Point(1, 2), Point(3, 4)]
    snapshot = copy points
    points[1].x = 10
    // snapshot[1].x == 3; points[1].x == 10
    return points[1].x - 10
}
```

`owner.field = value` и `owner[index] = value` заменяют значение корневой
`var`-привязки. Пути могут содержать несколько полей и индексов, например
`packet.headers[i].bytes[j] = byte`. Остальные части значения сохраняются;
ранее созданные копии остаются независимыми. Это не вводит идентичность объекта,
адресуемые поля или изменяемые ссылки.

Правила:

- Корень — существующая, полностью доступная `var`-привязка. Тип правой части
  точно совпадает с типом выбранного поля или элемента; литералы получают этот контекст.
- Индексы имеют тип `u32`. Вычисление идёт от корня по пути слева направо,
  каждый индекс вычисляется один раз, его границы проверяются сразу.
- Только после всех проверок пути вычисляется правая часть, ровно один раз.
  Затем корневая привязка получает обновлённое значение. Trap при вычислении
  пути не позволяет выполнить эффекты правой части.
- Некорректный индекс, включая константу или индекс пустого массива, вызывает
  runtime trap даже при неиспользуемом результате. Неисполняемая ветка не обновляет значение.
- Живое лексическое readonly-заимствование запрещает любое обновление владельца,
  включая элементы вне диапазона view. После окончания области заимствования
  обновления вновь разрешены. Копировать владельца при живом view можно;
  независимую `var`-копию можно обновлять.
- Нельзя перемещать корневого владельца при вычислении индексов или правой части.
  Нельзя создать заимствование владельца в правой части и одновременно обновить его.
- `move owner.field` и `move owner[index]` запрещены. Обновление части не
  восстанавливает перемещённую привязку: сначала требуется присвоить весь объект.
- Запись через `View`, в `.len`, в payload варианта или временное значение
  запрещена. Для вариантов остаются `match` и конструкторы.

В ветвлениях и циклах объединяются целые обновлённые значения.
Неполностью инициализированные структуры, mutable views, неявные деструкторы
и пользовательские ресурсные поля в эту версию не входят.

**Стоимость.** Логическая независимость не означает обязательного копирования
всего агрегата при каждой записи, но и не гарантирует O(1). Физические копии,
стековое размещение и устранение промежуточных значений зависят от backend
и оптимизации. Скрытые heap-аллокации, COW и счётчики ссылок не вводятся.
`insertvalue` сам по себе не является доказательством постоянной стоимости.

Пример: `examples/value_updates.liza`.


## Пользовательские модули 0.0.17

`import` задаёт зависимость от файла внутри корня проекта, `pub` экспортирует

## Линейные результаты и bounded Vec (0.0.20)

`(first, second) = expression` однократно вычисляет правую часть, потребляет
линейный результат целиком и создаёт две разные новые привязки. Ранее связанный
результат передаётся через `move`. Копирование, потеря ресурса, частичное
извлечение, вложенные шаблоны и хранение произведения в агрегате запрещены.

`vec.Vec<T>` допускает копируемые T, выделяет фиксированную вместимость в регионе
и предоставляет доступ только к `[0,len)`. `push/pop/set` возвращают вектор
безусловно, отдельно от статуса или элемента. `get/pop` создают независимые
значения; views блокируют изменение и завершение владельца.

[Полный контракт, API и границы стоимости](bounded-vec.md).

## Явное увеличение вместимости Vec (0.0.21)

`vec.reserve(move current, region, capacity)` требует `alloc` и возвращает
линейное произведение вектора и `Result<vec.Done, MemoryError>`. Регион должен
совпадать с доказанным происхождением вектора. Живой view запрещает вызов.

Запрос не больше текущей вместимости — no-op. При росте выделяется новое
размещение в том же регионе и копируется только `[0,len)`. Старое размещение
остаётся занятым. Отказ сохраняет вектор и состояние региона.
[Полный контракт](vec-reserve.md).
