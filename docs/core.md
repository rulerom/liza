# Исполняемое ядро 0.0.1

Это спецификация текущего прототипа, не полного языка Liza.

## Синтаксис

```text
program   := function*
function  := "fn" name "(" parameters? ")" "->" "u32" (":" "pure")? "{" statements "}"
parameters := name ":" "u32" ("," name ":" "u32")*
statement := name (":" "u32")? "=" expression | "return" expression
expression := literal | name | name "(" arguments? ")" | "(" expression ")"
            | expression operator expression
operator  := "+" | "-" | "*" | "+%" | "-%" | "*%"
```

Statement разделяется newline или `;`, перед `}` разделитель необязателен.
Заголовки функций и выражения пока однострочные. Комментарий `//` продолжается
до конца строки. Идентификаторы ASCII: `[A-Za-z_][A-Za-z_0-9]*`; `fn`, `return`,
`pure`, `u32` зарезервированы. Литералы десятичные либо `0x` hexadecimal.
Унарных операций и отрицательных литералов пока нет.

## Типы и имена

Единственный тип — `u32`, диапазон 0…4294967295. Литерал вне диапазона — ошибка
компиляции. Типы параметров и результата обязательны. Тип локальной привязки
выводится либо записывается явно. Неявных преобразований нет.

Привязка вводит имя значения; повторная привязка и затенение параметра запрещены.
Использовать имя можно только после объявления. Функции видимы во всём модуле,
включая forward calls; рекурсия разрешена, завершение не доказывается.
Имена функций и локальных значений находятся в разных пространствах:
`f(...)` всегда ищет функцию, простое `f` — локальное значение.

Каждая функция обязана закончиться `return`; код после него отклоняется.
Ровно одна `main() -> u32` без параметров обязательна во всех командах прототипа.
`: pure` необязательно: все доступные операции принадлежат чистому ядру.
Это пока ограничение набора конструкций, не полноценный анализ эффектов.

## Вычисление

Операнды и аргументы вычисляются слева направо, statements — в порядке исходника.
Умножение имеет более высокий приоритет, чем сложение и вычитание.
Операции одного приоритета ассоциируются слева.

`+`, `-`, `*` проверяют диапазон результата. Переполнение/выход ниже нуля
завершает программу через trap; продолжение с произвольным значением запрещено.
`+%`, `-%`, `*%` вычисляют по модулю 2^32. Обе политики одинаковы при `-O 0`
и `-O 2`. Потенциально падающие вычисления нельзя удалять без доказательства
их безопасности, даже когда результат не используется.

`return` из main передаёт результат host ABI как код завершения. ОС может
ограничивать его наблюдаемую ширину; POSIX shell видит младшие 8 бит.
Точный сигнал/код trap зависит от платформы; формат сообщения пока не задан.
Исчерпание памяти или стека не моделируется этим ядром.

## IR и backend

Liza IR хранит функции, типы, параметры, определения значений, зависимости,
контракт pure и политику overflow каждой арифметической операции. Проверка имён,
арности и диапазонов происходит до backend. JSON доступен через `emit-ir`.
IR пока не принимается на вход, отдельного verifier для внешнего IR нет.

LLVM backend понижает wrapping в обычные `add/sub/mul` без `nsw/nuw`,
проверяемую арифметику — в overflow intrinsics и условный переход к trap.
Семантика этих инструкций описана в
[LLVM Language Reference](https://llvm.org/docs/LangRef.html#arithmetic-with-overflow-intrinsics).
Оптимизацией и машинным кодом занимается Clang/LLVM; собственных проходов
оптимизации Liza ещё нет.
