# Исполняемое ядро 0.0.2

Это спецификация текущего прототипа, не полного языка Liza.

## Синтаксис

```text
program   := function*
function  := "fn" name "(" parameters? ")" "->" type (":" "pure")? block
type      := "u32" | "bool"
parameters := name ":" type ("," name ":" type)*
block     := "{" statements "}"
statement := name (":" type)? "=" expression | "return" expression | conditional
conditional := "if" expression block ("else" (block | conditional))?
expression := literal | "true" | "false" | name | name "(" arguments? ")"
            | "(" expression ")" | "!" expression | expression operator expression
operator  := "+" | "-" | "*" | "+%" | "-%" | "*%"
            | "==" | "!=" | "<" | "<=" | ">" | ">="
```

Привязки и `return` разделяются newline или `;`, перед `}` разделитель
необязателен. После блока `if/else` разделитель также необязателен.
`else` можно писать на той же или следующей строке; `;` перед `else` недопустим.
Заголовки функций и выражения пока однострочные. Открывающая `{` следует
на той же строке, что и заголовок функции, условие или `else`.
Комментарий `//` продолжается до конца строки.
Идентификаторы ASCII: `[A-Za-z_][A-Za-z_0-9]*`; `fn`, `return`, `pure`, `u32`,
`bool`, `true`, `false`, `if`, `else` зарезервированы.
Числовые литералы десятичные либо `0x` hexadecimal. Отрицательных литералов нет.

## Типы и имена

`u32` имеет диапазон 0…4294967295. Литерал вне диапазона — ошибка
компиляции. `bool` имеет два значения: `true` и `false`. Типы параметров и результата обязательны. Тип локальной привязки
выводится либо записывается явно. Неявных преобразований нет.

Привязка вводит имя значения; повторная привязка и затенение параметра запрещены.
Использовать имя можно только после объявления. Функции видимы во всём модуле,
включая forward calls; рекурсия разрешена, завершение не доказывается.
Имена функций и локальных значений находятся в разных пространствах:
`f(...)` всегда ищет функцию, простое `f` — локальное значение.

Каждый путь выполнения функции обязан закончиться `return` с результатом
объявленного типа. Достаточно `return` в обеих ветках `if/else`.
Код после безусловного возврата (в том числе после двух возвращающих веток)
отклоняется. Проверка структурная: даже `if true { return 1 }` без `else`
не считается полным возвратом, нужен последующий `return`.
Статически проверяются обе ветки, включая ветку с заведомо ложным условием.
Ровно одна `main() -> u32` без параметров обязательна во всех командах прототипа.
`: pure` необязательно: все доступные операции принадлежат чистому ядру.
Это пока ограничение набора конструкций, не полноценный анализ эффектов.

## Вычисление

Операнды и аргументы вычисляются слева направо, statements — в порядке исходника.
Приоритеты от высокого к низкому:

| Операции | Допустимые типы | Результат |
| --- | --- | --- |
| `!` | `bool` | `bool` |
| `*`, `*%` | `u32`, `u32` | `u32` |
| `+`, `-`, `+%`, `-%` | `u32`, `u32` | `u32` |
| `<`, `<=`, `>`, `>=` | `u32`, `u32` | `bool` |
| `==`, `!=` | Два значения одного типа (`u32` или `bool`) | `bool` |

Бинарные операции одного приоритета ассоциируются слева. Сравнения `u32`
беззнаковые: `0xffffffff > 1` истинно. Неявного преобразования числа в bool
нет; `if 1`, `true + 1` и `1 == true` — ошибки типов.
Для отрицания сравнения нужны скобки: `!(a < b)`.
`&&` и `||` пока не реализованы; составные условия можно выражать вложенными `if`.

`+`, `-`, `*` проверяют диапазон результата. Переполнение/выход ниже нуля
завершает программу через trap; продолжение с произвольным значением запрещено.
`+%`, `-%`, `*%` вычисляют по модулю 2^32. Обе политики одинаковы при `-O 0`
и `-O 2`. Потенциально падающие вычисления нельзя удалять без доказательства
их безопасности, даже когда результат не используется.

`return` из main передаёт результат host ABI как код завершения. ОС может
ограничивать его наблюдаемую ширину; POSIX shell видит младшие 8 бит.
Точный сигнал/код trap зависит от платформы; формат сообщения пока не задан.
Исчерпание памяти или стека не моделируется этим ядром.

## Ветвления и области видимости

```text
fn in_range(value: u32, minimum: u32, maximum: u32) -> bool {
    if value < minimum {
        return false
    }
    return value <= maximum
}

fn main() -> u32 {
    if in_range(42, 10, 100) {
        return 42
    } else {
        return 0
    }
}
```

`if` — инструкция, не выражение. Условие вычисляется один раз и должно иметь
тип `bool`. Выполняется только выбранная ветка; переполнение в невыбранной
ветке не приводит к trap. `else` необязательно. Поддерживаются вложенные
ветвления и цепочки `else if`.

Ветки видят предшествующие привязки внешней области. Объявленные в ветке имена
доступны только внутри неё и её вложенных блоков. Они не доступны в соседней
ветке или после `if`. Затенять видимое имя нельзя; одно и то же новое имя
можно независимо объявить в соседних ветках. После завершения области её имя
можно использовать для новой привязки. Изменяемых переменных пока нет.

## IR и backend

Liza IR версии 3 хранит типизированные параметры, значения и базовые блоки.
Каждый блок заканчивается `return`, условным `branch` или безусловным `jump`.
Ветвления сохраняются до backend; обе ветки не вычисляются заранее.
Контракт pure и политика overflow остаются явными.
Операции и функции имеют признак `may_trap`: у checked-арифметики он установлен,
у вызовов распространяется транзитивно по графу, включая рекурсивные функции.
Это консервативная оценка: наличие проверки даже в невыбранной ветке отмечает
возможный trap, а не обещает, что он произойдёт. `may_trap: false` не доказывает
завершение и не исключает исчерпания стека; такие отказы не моделируются ядром.

Trap — наблюдаемое аварийное завершение. Порядок операций внутри блока и пути
между блоками задают порядок выполнения потенциальных trap. Удаление проверки,
перестановка или перенос из условной ветки допускаются только при доказательстве
сохранения наблюдаемого поведения. Это относится к constant folding,
reassociation, strength reduction и будущим оптимизациям циклов.
`pure` исключает внешние эффекты, но не означает отсутствие trap. После будущих
преобразований IR сведения о возможных trap должны пересчитываться. Формат предыдущих версий изменён;
стабильность сериализованного IR пока не гарантируется.

Проверка имён, арности, типов, диапазонов и возврата на всех путях происходит
до backend. JSON доступен через `emit-ir`.
IR пока не принимается на вход, отдельного verifier для внешнего IR нет.

LLVM backend представляет `bool` как `i1`, `u32` как `i32`, сравнения — `icmp`,
ветвления — `br`. Wrapping понижается в обычные `add/sub/mul` без `nsw/nuw`,
проверяемая арифметика — в overflow intrinsics и условный переход к trap.
Семантика инструкций описана в
[LLVM Language Reference](https://llvm.org/docs/LangRef.html).
Оптимизацией и машинным кодом занимается Clang/LLVM; собственных проходов
оптимизации Liza ещё нет.
