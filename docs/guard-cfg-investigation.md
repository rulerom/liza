# Performance Parity P3 — один избыточный guard

Узкое исследование G0–G3 на LLVM 23. **Production backend, Core, runtime и исходники
JSON не изменены.** Внешнее преобразование Semantic IR обнаруживает неизменённое поле
за `phi` агрегата. Это позволяет стандартному LLVM устранить повторную проверку
переполнения. Оптимизация пока не включена в обычную компиляцию.

## G0: конкретные условия вместо общего числа ветвлений

Сопоставлены `utf8_stream.feed_byte` и внешний mutable feed Liza с inlined
`encoding_byte` и `stream_feed` Rust. Источники алгоритмов сохранены от прежнего
корпуса; compiler/stdlib snapshot — `899855a`. Ниже — локальная карта условий,
а не полная атрибуция разницы стоимости двух автоматов.

| Условие | Liza, default O2 | Rust O2 | Решение P3 |
| --- | --- | --- | --- |
| UTF-8 `position == U64_MAX` на входе | Возврат ошибки | Возврат ошибки | Необходимый guard сохранён |
| UTF-8 `position + 1` после успешного перехода | Повторный overflow intrinsic и trap edge | `add nuw`, без повторного guard | Единственная цель преобразования |
| UTF-8 status после helper | `switch error → Option phi → tag test` | Ошибки маршрутизируются внутри inlined CFG | Кандидат отдельного исследования; не изменён |
| JSON error после шага | Чтение и условный выход | Чтение и условный выход | Не объявляется лишним |
| Внешний JSON `position + 1` | Checked-add и trap | Сравнение с MAX и panic | Обязательное поведение сохранено |
| Глубина и индексы стека | Проверки зависят от пути | Проверки/диапазоны зависят от пути | Инвариант допустимости не принят за аксиому |

Первый guard уже исключает MAX. Между ним и последним increment меняются другие
поля `Utf8StreamState`, но исходное `position` остаётся тем же. После нескольких
`phi` LLVM не восстанавливает эту связь. В Semantic IR достаточно изменить источник
двух чтений поля: с результирующего агрегата на исходный value-параметр. Одно чтение
уже мёртвое; второе питает checked-add.

Правило не содержит имён JSON, UTF-8 или поля `position`. Оно принимает только
копируемую плоскую scalar-структуру, настоящий by-value параметр и pure-функцию.
Все входы `phi` должны происходить от одного параметра через изменения **других**
полей. Изменение выбранного поля, другой корень, цикл, ресурс или mutable-параметр
отклоняют преобразование. Это ограниченный эксперимент, не общий pass удаления
проверок или межпроцедурный анализ диапазонов.

## G1: проверка преобразования и граница доверия

В исходном и изменённом raw LLVM по-прежнему есть checked-add и trap edge.
Нормальный Clang O2 сам превращает последний increment в `add nuw` после forwarding.
В ARM64 assembly соответствующий участок меняется с `adds; b.lo; brk` на обычный
`add` и возврат. Это наблюдение машинного кода, а не доказательство LLVM lowering.

Независимый checker читает исходный Semantic IR и изменённый **raw LLVM IR**:

- отдельные исполнители моделируют CFG, `phi`, поля, обновления, unsigned-арифметику
  и traps через bitvectors/Bool;
- сравниваются все поля результата, наличие trap и полнота покрытия путей;
- все битовые значения параметров допустимы, включая некорректные состояния UTF-8;
- сертификаты преобразования, `may_trap` и storage summaries не служат аксиомами;
- неизвестные инструкции и циклы завершают проверку ошибкой, а не успехом.

Z3 5.3.1 дал **5 UNSAT**: baseline и candidate фактического UTF-8 helper, плюс три
контрольные функции. Это доказательство в рамках двух реализованных семантик для
выбранных функций. Soundness общего оптимизатора, всего frontend, LLVM passes и
машинного исполнения из него не следует. Исполнители и solver остаются доверенной
базой; существующие Verified-статусы не расширяются.

Два отрицательных контроля дали **SAT** на явно заданных контрпримерных входах:

1. Принять изменение выбранного поля на одном входе `phi` за изменение другого
   поля. При `position=0`, `other=MAX`, `flag=true` исходник обязан trap, ошибочный
   вариант возвращает `position=1`.
2. Удалить guard у безусловного increment. При `x=MAX` исходник обязан trap,
   ошибочный вариант возвращает ноль.

Контрпримеры воспроизведены отдельным нативным исполнением на O0/O2. Дополнительно
проверены несколько живых snapshots и обе ветви перехода. Всего 20 native runs;
8 тестов политики проверяют в том числе независимость от имён и отказ для циклов,
разных корней, resource/indirect/mutable форм и неизвестных инструкций checker.

## G2: результат на прежнем корпусе

Apple M4, Clang 23.1.4, Rust 1.99.1 / LLVM 23.1.3, generic CPU, O2, общий C ABI без
LTO. Шесть документов ~256 КиБ, чанки 2048 байтов, ~16 МиБ на sample. 10 перемешанных
серий, **180 измерений**. Это одна машина и одна серия; не межплатформенная гарантия.
Сравнение с Rust — одинаковая major-версия LLVM, не идентичные pipeline.

| Нагрузка | Default, МиБ/с | Forward, МиБ/с | Ускорение | Rust, МиБ/с |
| --- | ---: | ---: | ---: | ---: |
| ASCII | 191,6 | 215,9 | 1,127× | 400,2 |
| Unicode | 203,3 | 234,7 | 1,155× | 500,9 |
| Escapes | 198,0 | 238,7 | 1,206× | 456,0 |
| Numbers | 220,1 | 264,3 | 1,201× | 399,8 |
| Long string | 266,6 | 329,6 | 1,236× | 540,5 |
| Depth 64 | 166,4 | 183,8 | 1,105× | 280,0 |

До timing все варианты O0/O2 и Rust проходят 6785 независимо заданных partition
cases каждый; дополнительно 738 CLI checks. Инструментированные binaries сверяются
по всему partition probe, но никогда не используются для измерения скорости.

На каждой из шести нагрузок исчезают ровно **один conditional IR transfer и один
overflow intrinsic на входной байт**. На ASCII: 17,376 → 16,376 transfers/байт,
против 14,351 у Rust. Число state loads/stores и их allocation spans не меняется.
Это конкретная атрибуция одного guard, но не объяснение всего оставшегося разрыва.
Счётчики не измеряют hardware branches, mispredictions или реальный memory traffic.
Ноль overflow intrinsics у Rust не означает отсутствие checked-арифметики.

Стоимость:

- `.text`: 7188 → 7204 байта, **+16 байт (+0,22%)**;
- stack frame UTF-8 helper: 0 → 0; JSON feed и `stream_feed`: 64 → 64 байта;
- медиана отдельной компиляции raw LLVM → O2 object: 78,4 → 79,2 мс, по 5 запусков.
  Это диагностическое измерение, без frontend/исследовательского pass, не обещание
  постоянного overhead компилятора.

Цель ≥90% Rust пока не достигнута. Forward достигает примерно 47–66% Rust на этом
корпусе. Нельзя складывать проценты с историческими P1/P2; комбинация с Cost400
в этом узком эксперименте не измерялась.

## G3: другие программы и решение

У RTP parser и TCP relay **ноль применимых мест**. Секции машинного кода совпадают
побайтово: соответственно 1040 и 22916 байтов. Это проверка отсутствия изменений,
не свидетельство ускорения сетевых приложений.

30 существующих тестов проходят с исследовательским преобразованием на каждой
эмиссии LLVM: snapshots/traps, mutable audit и порядок I/O, RTP и реальные TCP
потоки с half-close, частичными записями, fault injection и повторным использованием
слотов. Проверка выполнена локально на macOS O0/O2; Linux/Windows не заявляются.
Первый запуск socket-тестов был заблокирован sandbox; полный повтор с разрешёнными
локальными сокетами прошёл. Оба журнала сохранены.

Результат достаточен для отдельного ревью узкого правила, но **production pass
не включён**. Нового синтаксиса и тяжёлого CI workflow нет. R0/VN0 и независимая
эксплуатационная приёмка Gateway сохраняют приоритет. Следующая оптимизация должна
так же иметь конкретное условие, проверяемую семантику и измеренный эффект.
