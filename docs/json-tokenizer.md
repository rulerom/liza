# T4 — потоковый JSON tokenizer и декодирование строк

**Проект контракта; реализация ещё не начата.** T3 уже предоставляет bounded
builder и потоковый format. T4 — отдельный библиотечный этап: события и значения
без DOM, новых builtin, возвращаемых views и resource mutable borrowing.

Предлагаемые модули — `text.json_tokens` и `text.json_decode`; имена и сигнатуры
ниже описывают контракт, а не существующий API. `json.*`, `liza-json check`
и первый formatter сохраняются самостоятельными регрессионными примерами.

## Два самостоятельных среза

| Срез | Результат |
| --- | --- |
| T4-A | События структуры и raw-фрагменты токенов с абсолютными и локальными диапазонами |
| T4-B | Декодирование JSON-строки в переданный Buffer с повторным использованием вместимости |

Raw-режим сохраняет исходные байты, включая quotes и escapes. Decoded-режим
выдаёт UTF-8 значение строки без кавычек, с обработкой escapes. Ни один режим
не требует хранения целого токена. Их корректность и стоимость проверяются
отдельно; первый срез не должен обещать готовность второго.

## Профиль JSON

Сохраняется профиль существующего валидатора: UTF-8 без BOM, один корневой JSON
value, глубина до 64 контейнеров, отсутствие комментариев и trailing commas,
обязательные пары escaped UTF-16 surrogates. Ключи не сортируются и не
дедуплицируются. Числа остаются исходными лексемами; преобразование в целые
числа или floating-point не входит в T4.

Tokenizer проверяет также грамматическую последовательность токенов.
Например, отсутствие двоеточия, лишняя запятая и второй корень не превращаются
в успешную последовательность событий. Это не самостоятельное построение DOM.

## События T4-A

| Событие | Смысл |
| --- | --- |
| ObjectStart / ObjectEnd | Начало / конец объекта, диапазон одного байта |
| ArrayStart / ArrayEnd | Начало / конец массива, диапазон одного байта |
| StringStart | Начало строки; роль Key или Value и абсолютное начало |
| StringPart | Непустой raw-фрагмент строки из текущего чанка |
| StringEnd | Полный диапазон лексемы, включая кавычки; признак наличия escapes |
| NumberStart / NumberPart / NumberEnd | Аналогичная последовательность для числовой лексемы |
| True / False / Null | Завершённая лексема и её абсолютный диапазон |
| DocumentEnd | Успешный EOF после ровно одного корневого value |

Comma, colon и whitespace проверяются, но отдельными событиями не выдаются.
String в позиции имени свойства имеет роль Key; остальные строки — Value.

Для одного токена конкатенация всех Part точно равна исходной лексеме:
без вставок, пропусков или повторов. Для строк сюда входят обе кавычки,
поэтому даже пустая строка имеет raw-лексему из двух байтов. Start/End —
метаданные, они не дублируют байты в этой конкатенации.

Part не обязан совпадать с кодовой точкой или escape. Он может заканчиваться
внутри UTF-8, `\uXXXX` или пары surrogates. Raw-фрагмент поэтому не является
TextView или самостоятельной UTF-8 строкой.

StringEnd появляется после закрывающей кавычки. NumberEnd требует допустимого
разделителя либо EOF: `1e`, `-` и `01` не получают успешного NumberEnd.
Разделитель не входит в NumberPart и обрабатывается следующим грамматическим
переходом, без пропуска и повторного счёта позиции.

## Диапазоны и жизнь входа

Каждый шаг получает readonly `View<u8>` и курсор `u32` внутри текущего чанка.
Событие содержит числа и признаки, **не View**:

- `begin/end: u64` — абсолютные полуоткрытые диапазоны в исходном потоке;
- у Part дополнительно `local_start/local_end: u32` — диапазон в текущем view;
- `next: u32` — первый ещё не потреблённый байт текущего чанка.

Для Part выполняется `0 <= local_start < local_end <= input.len`.
Абсолютные координаты соответствуют базовой позиции этого чанка плюс локальному
диапазону; арифметика должна проверяться до сложения. Начало полного токена может
относиться к предыдущему чанку и не является индексом текущего view.

Вызывающая сторона может создать локальный subview по этим координатам и
обработать его до изменения/переиспользования входного буфера. Tokenizer не
удерживает ссылку на вход. Диапазон — описание данных, а не право доступа и не
владелец: хранение чисел не продлевает жизнь старого содержимого. Если событие
сохраняется надолго, потребитель должен отдельно владеть исходником или скопировать
нужные байты. Применять старые локальные координаты к новому чанку запрещает
контракт потребителя, а не числовой тип координат.

До NeedInput все события, которым нужны диапазоны старого чанка, должны быть
выданы и обработаны. После NeedInput вход можно переиспользовать. State хранит
только фиксированное состояние, offsets и ограниченный pending-event; полного
токена, произвольного префикса или скрытой копии чанка в нём нет.

Строка целиком в текущем чанке без escapes допускает readonly-доступ к
`[begin+1,end-1)` после успешного StringEnd и перевода в локальные координаты.
Если строка пересекает чанки, единого непрерывного view не обещается.

## Шаг, backpressure и EOF

Предлагается pull-интерфейс: один шаг возвращает не более одного события,
обновлённый курсор и явное состояние продолжения.

| Исход | Действие потребителя |
| --- | --- |
| Event | Обработать событие и продолжить с next |
| NeedInput | Передать следующий чанк либо объявить EOF |
| NeedOutput (decoder) | Обработать выходной префикс и предоставить вместимость |
| Done | У tokenizer выдан DocumentEnd; у decoder завершена текущая строка |
| Error | Первый код и offset сохраняются; успешных событий больше нет |

Шаг не обязан потреблять байт: NumberEnd перед разделителем и выдача уже
готового события могут оставить next прежним. Но такие переходы должны
исчерпывать ограниченное pending-состояние. Нельзя бесконечно возвращать один
Event без изменения состояния. NeedInput на пустом чанке не означает прогресс;
вызывающий код не должен повторять тот же пустой ввод в busy-loop.

EOF передаётся явно после потребления последнего чанка. Финализация может
выдать NumberEnd, затем DocumentEnd. Незавершённые строки, escapes, Unicode и
контейнеры заканчиваются Error, а не DocumentEnd. Режим EOF терминален:
после его объявления новый feed не разрешён. Это отличается от snapshot
`json.finish`; поведение прежнего валидатора не меняется.

События до DocumentEnd описывают принятый префикс, а не валидность всего документа.
Даже NumberEnd или StringEnd не являются транзакционным подтверждением
всего JSON. Потребитель с внешними эффектами выбирает собственную политику commit.

## T4-B — декодирование в предоставленный буфер

Decoder принимает raw JSON-строку, включая кавычки, порциями и проверяет
её независимо. Public API не должен доверять тому, что произвольный вход
обязательно пришёл от tokenizer. Он не принимает грамматику окружающего объекта.
После закрывающей кавычки decoder завершает строку и оставляет последующие
байты входного view непотреблёнными; next указывает сразу за кавычку.
Для следующей строки создаётся новое состояние. Это не DocumentEnd всего JSON.

Поддерживаются `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`,
`\uXXXX` и пары surrogates. `\u0000` выдаёт байт NUL; длина явная, а не
C-string. High surrogate ожидает обязательный low surrogate; одиночные
surrogates и значения за пределами Unicode scalar values отвергаются.
Escaped числа и суррогаты декодируются в UTF-8, без Unicode normalization.

Буфер принадлежит вызывающей стороне. Первый API использует потребление
`Buffer<u8>` с возвратом владельца на **всех** исходах. M0 изменяет только
копируемое состояние decoder; mutable borrow ресурсного Buffer/String не нужен.

На каждом шаге возвращается `produced <= capacity`; полезный диапазон
выходного буфера — `[0,produced)`. Он состоит из полных UTF-8 последовательностей.
Остальные байты не являются текстом. Перед повторным вызовом потребитель должен
обработать этот префикс; его локальные views завершаются до передачи владельца
обратно decoder.

Кодовая точка не делится между выходными порциями. При нехватке места допустимо
уже потребить часть raw-входа и сохранить один декодированный scalar (до четырёх
байтов). NeedOutput сообщает минимальную вместимость для него и точный next;
повторно подавать уже потреблённый escape нельзя. Буфер нулевой или недостаточной
вместимости даёт NeedOutput, а не trap. Вместимость не менее четырёх байтов
достаточна для прогресса при регулярном потреблении результата.

Состояние хранит только конечный автомат, текущий hex accumulator, возможный
high surrogate, неполный UTF-8 scalar и небольшой pending-output. Размер строки
не увеличивает память decoder. Накопить всё значение в String можно отдельно,
с явным бюджетом и ожидаемым Full.

Нельзя отбросить raw-префикс, а при обнаружении позднего escape запросить его
декодирование задним числом. Режим обработки выбирается заранее: либо decoder
получает все raw-фрагменты, либо потребитель сам сохраняет/перечитывает исходник.
Возможность zero-copy для одной короткой строки не означает zero-copy всех строк.

## Ошибки, offsets и стоимость

Смещения ошибок всегда относятся к **исходному JSON**, а не к декодированному
UTF-8. Decoder принимает абсолютную базу строки и сохраняет её при смене чанков.
Правила приоритета совпадают с check: UTF-8 проверяется до JSON-перехода,
некорректный escape указывает на отвергнутый байт, непарный surrogate — на
начальную обратную косую черту, незавершённый ввод — согласно текущему профилю
EOF. Тесты сопоставляют точные kind/offset с существующим валидатором.

Некорректный локальный курсор и нехватка выхода — отдельные ошибки API/ресурса,
не Syntax. Переполнение абсолютного счётчика даёт SizeOverflow до арифметического
trap. При ошибке уже выданные события/байты не отзываются; неоконченная строка
не считается принятой. Владелец output возвращается и на Error.

Память — фиксированный стек глубины 64, постоянное состояние и буферы вызывающей
стороны. Аллокаций, роста коллекций и повторного сканирования всей уже прочитанной
лексемы в горячем цикле нет. Корпус и бенчмарки оценивают фактическую стоимость
lowering отдельно; заранее обещать паритет с C++/Rust нельзя.

## Критерии приёмки

- Исходные lexemes восстанавливаются из raw Parts побайтово; полные spans,
  роль Key/Value и порядок структурных событий корректны.
- Пустые строки, NUL, multibyte UTF-8, каждый escape и surrogate pairs проверены
  на границах чанков; split может попадать между любыми двумя байтами.
- Нормализованная последовательность событий и декодированные значения
  не зависят от разбиения. Границы отдельных Part могут отличаться.
- Исчерпывающий перебор разбиений малых образцов, включая пустые чанки;
  случайные и граничные разбиения длинных токенов. Это конечные тесты,
  а не универсальное доказательство partition invariance.
- Decoder проверяется с вместимостью 0, 1, 2, 3, 4 и большим буфером,
  многократным NeedOutput, точным next и отсутствием потери pending scalar.
- Входной буфер реально перезаписывается между чанками; старый view не удерживается.
- Длинные строки/числа и лимиты 64/65 не превращаются в скрытый DOM;
  полное число не обязано помещаться в output.
- Ошибки, EOF, invalid cursors и предельные u64 проверены без неожиданных traps.
- O0/O2 на Linux/macOS/Windows; независимый oracle для событий/decoded values,
  прежние check/format/builder остаются регрессиями.
- Core, Semantic IR, runtime и V0–V4 не меняются. Ни CI, ни T4 не выставляют
  end-to-end verified и не доказывают soundness всей borrow-модели.

Следом можно проектировать lexer Liza: владелец исходника, byte ranges и
стабильные идентификаторы токенов. Это не требует вводить хранимые ссылки
или пользовательские lifetime-параметры вместе с T4.
