# Экспериментальные scoped workers

`workers.run(count)` запускает группу из 1–8 нативных потоков и ждёт завершения
всех до возврата. Каждый поток вызывает одну функцию `worker` из входного
модуля с уникальным ID от 0 до `count - 1`:

```liza
fn worker(id:u32)->u32 {
    return id + 1
}

fn main()->u32:io {
    result = workers.run(4)
    if result >> 32 != 0 {return 1}
    if u32.wrap(result) != 4 {return 2}
    return 0
}
```

Старшие 32 бита результата содержат статус: 0 — успех, 1 — неверное число
потоков, 2 — ошибка создания потока или синхронизации при запуске. При успехе
младшие 32 бита содержат XOR результатов всех workers; при ошибке они равны
нулю. Такой ограниченный формат экспериментальный и не является API очередей.
Запуск потоков имеет эффект `io`. Нативные стеки и объекты синхронизации
создаются ОС; их стоимость и размер не входят в региональные бюджеты Liza.

Функция `worker` должна быть негeneric, иметь сигнатуру `(u32)->u32`, эффект
`pure` и параметры по значению. Компилятор проверяет контракт и фиксирует
выбранную функцию в Semantic IR. Здесь нет передачи ресурсов, заимствований,
ссылок или изменяемого состояния между потоками. Работа с сокетами, регионами,
очередями и произвольными функциями остаётся следующим этапом. Данный срез не
позволяет написать многопоточный Gateway или RTP fanout.

При ошибке создания группа не запускает код функции: ранее созданные потоки
получают отмену и завершаются через join. Успешный вызов возвращается только
после join всех работников. Если worker не завершается, вызывающая сторона
тоже не завершит вызов; для trap автоматический cleanup не обещан. При
неожиданной ошибке системной синхронизации во время join runtime аварийно
завершает процесс, чтобы не оставить потоки со ссылками на истёкший стек.
