# Экспериментальные scoped workers

`workers.run(count)` запускает группу из 1–8 нативных потоков и ждёт завершения
всех до возврата. Каждый поток вызывает одну функцию `worker` из входного
модуля с уникальным ID от 0 до `count - 1`:

```liza
fn worker(id:u32)->u32 {
    return id + 1
}

fn main()->u32:io {
    result = workers.run(4)
    if result >> 32 != 0 {return 1}
    if u32.wrap(result) != 4 {return 2}
    return 0
}
```

Старшие 32 бита результата содержат статус: 0 — успех, 1 — неверное число
потоков, 2 — ошибка создания потока или синхронизации при запуске. При успехе
младшие 32 бита содержат XOR результатов всех workers; при ошибке они равны
нулю. Такой ограниченный формат экспериментальный и не является API очередей.
Запуск потоков имеет эффект `io`. Нативные стеки и объекты синхронизации
создаются ОС; их стоимость и размер не входят в региональные бюджеты Liza.

Функция `worker` должна быть негeneric, иметь сигнатуру `(u32)->u32`
и параметр по значению. Ей разрешено создавать и закрывать собственные
регионы, буферы и reactor; для этого она объявляет `io,alloc`. Компилятор проверяет контракт и фиксирует
выбранную функцию в Semantic IR. Здесь нет передачи ресурсов, заимствований,
ссылок или изменяемого состояния между потоками. Вызовы runtime проверяются транзитивно: разрешены только отобранные
операции reactor и локальной памяти. Регистрация process-wide обработчика
shutdown, консольный и файловый I/O, обычный UDP и вложенный `workers.run`
пока отклоняются. Передача ресурсов и очереди остаются следующим этапом. Данный срез не
позволяет написать многопоточный Gateway или RTP fanout.

При ошибке создания группа не запускает код функции: ранее созданные потоки
получают отмену и завершаются через join. Успешный вызов возвращается только
после join всех работников. Если worker не завершается, вызывающая сторона
тоже не завершит вызов; для trap автоматический cleanup не обещан. При
неожиданной ошибке системной синхронизации во время join runtime аварийно
завершает процесс, чтобы не оставить потоки со ссылками на истёкший стек.

## Границы runtime

Идентификатор reactor выделяется общим атомарным счётчиком без повторного
использования и без переполнения. Атомарность счётчика обеспечивает только
уникальность ID, не синхронизацию операций с reactor: каждый reactor остаётся
под исключительным управлением своего worker. Для Windows каждый созданный
сетевой handle сохраняет существующий контракт `WSAStartup` / `WSACleanup`.

Обработчик завершения и его регистрация принадлежат процессу. Пока worker
не может зарегистрировать обработчик или опросить его; вызывающая сторона
ожидает завершения всех workers и в это время не выполняет Liza-код. Гарантия
этого среза не распространяется на произвольные внешние потоки, внедрённые
через C, и не доказывает потокобезопасность всего runtime. `pure` сам по себе
не означает отсутствие изменения через `borrow mut`; здесь изоляция строится
на скалярной границе, проверке доступных операций и локальном владении.
