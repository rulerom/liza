# T2 — readonly-доступ к ресурсным структурам

**Статус: проект контракта, не реализован.** T1 и ресурсные структуры завершены
в [PR #15](https://github.com/rulerom/liza/pull/15), merge `f41efbd`.
Эта страница не меняет действующий Core и не разрешает новые программы.

Цель T2 — наблюдать пользовательский ресурсный тип на время вызова, сохраняя
владельца у вызывающей стороны. Первый результат — длина, вместимость и чтение
байтов String без потребляющего `inspect`. Возвращаемые TextView не требуются.

## Предлагаемая форма

Предварительный синтаксис параметра — `borrow value:Type`. Слово `borrow`
обозначает исключительно readonly-доступ в этом срезе. Это не новый хранимый
тип и не пользовательский указатель. Примеры ниже пока не компилируются:

```text
// Внутри модуля text.string, где доступны приватные поля.
pub fn length(borrow value:String)->u32 {
    return value.length
}

n = text.string.length(current)
next = text.string.clear(move current) // loan закончился после возврата length
```

На стороне вызова передаётся доступная именованная привязка без `move`.
Временные владельцы в borrowed-позиции первого среза запрещены: у них должен
быть явный владелец, который завершит ресурс после вызова.

Параметр доступен только для наблюдения. Он не создаёт обязанность закрыть
ресурс в callee и не снимает такую обязанность с caller. Нормальный возврат
оставляет владельца доступным; trap по-прежнему не обещает cleanup.

## Разрешения внутри функции

| Действие | Первый контракт |
| --- | --- |
| Читать доступное скалярное поле | Да, получается независимое значение |
| Читать копируемое поле-значение | Да, обычная семантика снимка; стоимость зависит от размера |
| Обратиться к вложенному ресурсному полю | Только как к readonly-проекции исходного владельца |
| Передать владельца/проекцию другому borrow-параметру | Да, loan ограничен вложенным вызовом |
| Скопировать или присвоить ресурсную проекцию новой owned-привязке | Нет |
| Move, потребляющий разбор, close, release, обновление | Нет |
| Вернуть или сохранить заимствованный ресурс/view | Нет |
| Читать приватное поле из чужого модуля | Нет |

Доступ к полю ресурса не должен создавать обычное owned SSA-значение: это путь
readonly-доступа с известным корневым владельцем. Проверка приватности выполняется
для каждого шага пути. Наличие borrow не позволяет извлечь приватный Buffer из
публичного String. Для owned-структур без borrow ограничения T1 не меняются.

Readonly относится ко всему достижимому хранилищу, а не только к битам дескриптора.
Функция не может передать поле-буфер сетевому чтению и тем самым изменить строку.

## Время жизни и порядок аргументов

Аргументы вычисляются слева направо. Loan начинается при вычислении borrowed-
аргумента и остаётся активным до возврата всего вызова. Поздний аргумент не может
переместить, завершить или изменить уже заимствованного владельца. При обратном
порядке проверка доступности должна обнаружить use-after-move.

Два readonly-заимствования одного владельца совместимы. Borrow целого владельца
консервативно блокирует все его поля; доказательство непересечения полей для
одновременной мутации не входит в T2. Вложенный вызов не продлевает loan за пределы
исходного вызова. Заимствование не создаёт новой идентичности буфера или региона.

Зависимости от региона сохраняются при каждом reborrow. Если callee одновременно
получил borrowed-буфер и owned-регион, закрытие региона всё равно должно быть
запрещено по совпадающему origin, включая случай временных аргументов.
На CFG joins учитываются все возможные корни; неизвестное происхождение нельзя
считать отсутствием loan. Для первого среза неоднозначные проекции можно отвергать.

## Почему недостаточно borrowed_params

В текущем компиляторе `borrowed_params` описывает доступ к ресурсному аргументу
без передачи владения. Это **не гарантия readonly**. Например, операции reactor
изменяют состояние сокетов, а `memory.alloc` меняет состояние региона, хотя
соответствующие аргументы заимствуются.

Нужен отдельный режим доступа в сигнатуре и Semantic IR: owned / readonly,
отличимый от существующих привилегированных адаптеров. Тела пользовательских
readonly-функций проверяются, а не объявляются trusted_library. Информация о
режиме должна сохраняться при разрешении вызовов и инстанцировании типов.

Каждая builtin-операция, которой передаётся readonly-проекция, должна иметь явный
контракт доступа. В начальный список входят `memory.len/view` и наблюдающие
`vec.len/capacity/get/view`. Общего разрешения на все borrowed_params нет.
`memory.set/alloc/close/release`, `vec.push/pop/set/reserve/release` и изменяющие
операции сетевого I/O через такую проекцию запрещены.

Эффекты остаются отдельной осью. Readonly-функция может выводить диагностику с
эффектом `io`, если не меняет заимствованный ресурс. И наоборот, `pure` сам по себе
не гарантирует отсутствия изменения логического владельца.

## Два среза реализации

**T2-A — readonly-параметр и проекции.** Конкретные ресурсные структуры, в том числе
уже конкретизированные generic-структуры, вложенные поля и наблюдающие операции.
Для String появляются непотребляющие `length/capacity/byte_at`. Первый срез не
требует общего borrowed-match ресурсных вариантов, пользовательских alias-
привязок, generic borrow-функций или возвращаемых ресурсов, зависящих от borrow.
Результат такого наблюдающего вызова — независимое копируемое значение без loans.

**T2-B — локальный байтовый view.** View создаётся и используется внутри callee,
может передаваться вложенному наблюдающему вызову, но не выходит из функции.
В существующем Core `view a[start..end]` принимает массив, а не другой View.
Поэтому диапазон `[0,length)` для String — отдельная часть реализации, а не уже
доступная операция. Предлагается локальный subview существующего View с проверкой
границ и наследованием **исходного корня loan**, а не временем жизни переменной view.

Пример желаемого поведения T2-B, также не реализованный:

```text
pub fn write(borrow value:String)->Result<u64,IoFailure>:io {
    bytes = memory.view(value.storage)
    prefix = view bytes[0..value.length]
    return console.write_bytes(prefix)
}
```

Нельзя передать полный capacity вместо length: хвост после clear не является
содержимым String. Такой байтовый view сам по себе не называется TextView и не
даёт нового доказанного UTF-8 типа. Возврат `bytes(value)->View<u8>`, поля с views,
замыкания и долгоживущие срезы остаются вне обоих срезов.

## Приёмочные проверки

| Положительный контроль | Обязательный отрицательный контроль |
| --- | --- |
| Length не потребляет String; последующий clear разрешён | Move/clear/release внутри borrow запрещены |
| Два readonly-аргумента одного владельца допустимы | Более поздний аргумент потребляет уже заимствованного владельца |
| Наблюдение вложенного публичного поля | Обход приватности через borrowed-проекцию |
| Buffer сохраняет origin через вложенные вызовы | Закрытие того же региона через второй аргумент |
| Локальный view передаётся во вложенную функцию | Возврат view, сохранение его в агрегат или escape владельца |
| Clear после завершения вызова допустим | Mutation через builtin с borrowed_params, но без readonly-контракта |
| Передаются ровно length байтов строки | Чтение старого хвоста после clear, выход subview за границы |
| Ветви и поддерживаемые циклы сохраняют loans | Потеря loan на phi/backedge или при reborrow |

Нативные тесты должны исполняться при O0/O2 на Linux/macOS/Windows; отдельно
проверяются отсутствие копирования всего буфера и работа с runtime-входами.
Проверки Core должны включать согласованность сигнатур, параметров доступа в IR,
нормального выхода и порядка аргументов. Расширение нельзя принимать по одному
успешному примеру String: нужны независимые пользовательские типы-контроли.

V0–V4 и Relay остаются регрессиями прежних фрагментов. Их успешный CI не является
доказательством soundness T2. Формальная проверка новых правил требует отдельной
модели и отрицательных контролей, без автоматического расширения старых гарантий.

## Порядок после T2

T3 — StringBuilder, целые числа и экранирование; T4 — отдельный JSON tokenizer
с явно различимыми исходными диапазонами и декодированными значениями;
T5 — lexer Liza на Liza. Инвариант owned String не ослабляется ради входных
чанков: незавершённые UTF-8 последовательности хранит отдельный накопитель.
